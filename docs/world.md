- `water_trace.glsl`을 절반 해상도 반사와 경계 보충에서 공유한다. 기하학적 면 노멀과 기존 잔물결 노멀을30%로 혼합해 반사 방향만 완화하고, 광선이 수면 안쪽 반구로 뒤집히지 않게 보정한다. 시작점은 기하 노멀 방향0.02블록, 최초 탐색은0.03블록이며 수면 반대편 불투명 픽셀은 제외한다. 물결 원래 노멀은 기존 UV와 반사량 계산에 사용한다.
- 탐색 상한은 현재 렌더 컬럼 반경×16블록(16..1024), 마지막15%에서 거리 페이드다. 기본12컬럼은192블록,36컬럼은576블록이다. 이전 고정96블록/48단계 탐색을 RG32F 최소/최대 깊이 피라미드의 화면 공간 셀 탐색으로 교체한다. 광선을 화면/near/far에 잘라 투영한 뒤 겹치지 않는 깊이 범위는 큰 셀 단위로 건너뛰고 교차 후보는 원래 깊이까지 내려간다. 광선당 최대128회이며 예산 소진이나 화면 이탈은 하늘 반사로 복귀한다. 상한 거리까지 항상 교차를 찾는다는 보장은 아니다.
- Hi-Z는 원래 화면 크기부터1×1까지 생성한다. mip0은 불투명 D32 복사본의 깊이를 RG 두 채널로 읽고 이후 mip은 이전 단계의 min/max를 축소한다. 홀수 크기는 정규화 영역에 걸치는 최대3×3 입력을 포함하여 마지막 행/열과 경계 깊이를 누락하지 않는다. SSR OFF는 피라미드 생성과 반사/경계 추적을 모두 생략한다.
- 절반 해상도 RGBA16F의 alpha는 수면까지의 부호 있는 거리(수평면 양수/옆면 음수/빈 픽셀0)다. 본 패스는4탭을 각자의 화면 좌표에서 복원해 현재 수면 평면과의 오차·방향·불투명 가림을 검사한다. 유효 샘플 가중치 합이0.9 이상이면 합/가중치로 정규화하며, 가중치가 작다고 반사량 자체를 하늘색으로 약화하지 않는다. 부족한 경계 픽셀만 공용 Hi-Z 추적을 원래 해상도에서 수행한다. 반사 대상 색도 확인된 픽셀을 직접 읽어 옆 고체/하늘 색의 필터 누출을 줄인다.
- 자원은 기존 frame slot별로 소유하며 일반 프레임의 CPU/GPU 대기를 추가하지 않는다. 피라미드 추가 메모리는 보통 화면 픽셀당 약21.3bytes(진행 중2프레임 합계),1080p에서 약42MiB이며 전체 물 효과 이미지는 약86MiB다. 정렬/드라이버 메모리는 별도이고 아주 긴 창 비율에서는 mip 합계가 달라진다. 기존처럼 처음 효과 사용 시 확보하고 OFF여도 월드 종료까지 보관한다. 피라미드 작성과 경계 보충의 실제 GPU 비용은 미측정이다.
- 화면 밖/가려진 면/물 자체는 반사할 수 없고 시간 누적 안정화도 없다. 얇은 물체·깊이 불연속·이동 시 변화는 여전히 한계다. 소스 검토만 완료했으며 컴파일/빌드/실행/자동 테스트는 하지 않았다.

## 물 높이·깊이 표현·잔물결·SSR (2026-09-21, 소스 반영·미빌드)

- 후속 사용자 비스듬한 시선의 과도한 투명도 제보와 `실시`로 반사 곡선만 `F=.02+.98*(1-cosine)^3`으로 수정했다. 아래 초기 Schlick 지수5를 대체하는 시각적 조정이며 F0와 흡수/SSR/옵션은 유지한다. 평평한 수면 위30°/20°/10° 시선의 반사량은 약14.3%/29.9%/57.3%다. 미빌드 상태다.

- 사용자 `실시` 승인 범위: 공기에 노출된 최상단 물 높이7/8, 깊이에 따른 색/투명도, 잔물결, 프레넬 반사+SSR, 옵션의 전체/개별ON/OFF와 자동 저장이다. 기본값은 모두ON이다. SSR 실패 영역은 시간대의 하늘색과 표면 하늘광으로 보완한다. 물 흐름·새 물리·굴절 왜곡·물속 전체 화면 안개는 추가하지 않는다.
- `mesh_chunk`가 물 바로 위 셀이 공기이면 해당 셀의 모든 면에 PackedFace bit27을 기록한다. 위쪽 청크가 필요한 경우 기존 실제 halo를 읽는다. `world.vert`가 그 셀의 로컬 Y를7/8배 해서 윗면과 옆면 상단을 함께 낮춘다. 아래 물/천장에 덮인 물은 높이1, 최하단은 그대로다. 해수면 규칙은 y<192 물 배치를 유지하고 보이는 최상단은 Y191.875다. 물 블록 저장/충돌/조명 자료는 변경하지 않으며 F4와 효과OFF도 같은 높이를 사용한다. 면 데이터는 여전히4bytes, bit26의AO 대각선과 기존 재질/밝기 비트는 보존한다.
- `WaterSettings`는 enabled/depth/waves/ssr 네 boolean이다. settings schema3에 water 객체로 저장하고 v1/v2에서는 모두ON 기본값을 사용한다. 시작 메뉴와 Esc 옵션은 동일한 값을 즉시 적용한다. master OFF는 하위 체크를 비활성화하지만 선택값을 보존하며 모두OFF도 기본 파이프라인을 사용한다. 쓰기는 기존 옵션 변경 저장 경로로만 수행하며 기존 out/Sandbox/settings.json이나 worldgen.json을 이번 작업에서 직접 수정하지 않았다.
- 렌더 순서: 불투명 지형/플레이어 → 필요 시 색/깊이 snapshot → SSR이 켜졌으면 Hi-Z 생성과 물 메시의 절반 해상도 반사 패스 → 원래 해상도의 물 합성/경계 보충 → UI. snapshot에는 물과UI가 포함되지 않는다. 수면 재질만 별도 `WaterEffects`로 처리하고 청크 로딩/메시 공개 규칙은 그대로다. F3 삼각형 수에는 추가 SSR 물 그리기도 포함한다.
- 깊이 표현은 D32 깊이를 역행렬로 복원하고 시선이 물을 통과하는 거리로 RGB 투과율 `exp(-[.16,.055,.028]*거리)`을 계산한다. 바닥/불투명 색과 기존 물 텍스처를 섞은 색으로 흡수 효과를 표현한다. 거리 상한64, 하늘 깊이는64를 사용한다. 물 뒷면을 보는 경우 카메라→수면 거리를 사용한다. 합성한 장면을 다시 알파 혼합하지 않도록 깊이 효과ON은 최종alpha1을 사용한다. OFF는 기존 텍스처alpha×.72이며 SSR은 이때도 합성 alpha를 보정한다. 이는 현재 UNORM 장면 색을 사용하는 실용적인 흡수 근사다.
- 잔물결은 별도 에셋 없이 공유GLSL의 해석적 높이 미분으로 애니메이션 노멀을 만든다. 32블록 주기의 세 사인 성분이며 camera-relative 좌표+카메라XZ modulo32를 써서 청크/131072 순환 경계에 이어진다. 노멀과 미세UV만 바꾸고 메시나 물리 높이는 움직이지 않는다. 멀거나 비스듬히 보는 곳의 미해상 물결은 derivative로 약화한다. 위상은 move_player의 기존 유효 경과시간으로 누적하므로 메뉴/Esc/F8에서는 멈추며 시간 앞뒤 이동과는 독립이다.
- SSR은 가로/세로 각각 ceil(화면/2), 물 메시만 그리며 독립 깊이와 불투명 snapshot으로 가림을 처리한다. 초기 구현의48스텝/96블록/6회 세분화와 거리 차 기반 보간은 위 물 반사 보정 절의 Hi-Z/수면 평면 보간으로 대체했다. 반사량은F0=.02/지수3이며 화면 밖/가려진 물체/물 자체의 반사는 지원하지 않는다.
- 전체OFF/F4/보이는 물 메시 없음은 snapshot/반사/물 효과 셰이더를 건너뛴다. SSR OFF는 Hi-Z와 반사 패스를 생략하고 깊이OFF+잔물결만ON이면 snapshot 복사도 생략한다. 버퍼/파이프라인은 처음 필요한 때 생성하여 토글 시 재사용하고 화면 크기가 달라질 때만 재생성한다. OFF로 바꿔도 이미 확보한 버퍼 메모리는 월드 종료까지 보관한다. 초기 이미지 약22bytes/화면픽셀에 Hi-Z가 추가되었으며 현재 메모리/성능 한계는 위 물 반사 보정 절을 따른다.

## 노이즈 조건의 해변 표면 규칙 (2026-09-21, 소스 반영·미빌드)

- 사용자 `실시` 승인 범위는 같은 X/Z의 기존 노이즈와 수직 표면 정보만으로 해변 재질을 정하는 것이다. 수평 이웃 블록/높이/물, 주변 최고점, 실제 경사도, 물까지의 거리는 조회하지 않는다. 이전의 모든 육지 잔디 규칙보다 이 절을 우선한다.
- `terrain.cpp::assign_surface_rules`의 초기 조건: 가장 높은 고체의 윗면 `surface_y+1`이 `[192,196]`, Groundness가 `[-0.2,0.1]`, Smoothness가 `>=0`이면 모래 해변이다. 범위 끝은 포함한다. Groundness는 기존 공유 워핑을 반영하고 Smoothness는 기존처럼 원좌표의 신호다. Smoothness 조건은 지역 분류이며 실제 경사도 판정은 아니다. 강/호수와의 거리나 바다 연결성을 검사하지 않으므로 조건을 만족하는 내륙 낮은 지대에도 모래가 생길 수 있다.
- 수중 여부는 기존 `surface_y>=0 && surface_y+1<192`를 유지한다. 수중과 해변은 최고 고체부터 수직 깊이0..2 모래,3..4 흙,5 이상 돌이다. 나머지는 깊이0 잔디,1..3 흙,4 이상 돌이다. 깊이는 고체 개수가 아닌 Y 차이이며 빈 공간은 채우지 않는다. 가장 높은 표면만 코팅하고 동굴 안의 별도 바닥에는 적용하지 않는다.
- `generate_tile`이 기존 최고 고체 검색 후 `TerrainSite::sandy_surface`를 채운다. 해변 높이 후보만 모아 해당 블록 중심 `(x+0.5,z+0.5)`에서 Groundness/Smoothness를 SIMD 배치 계산한다. 최대256좌표/컬럼이며 후보가 없으면 추가 노이즈 계산을 하지 않는다. 수중은 노이즈 판정 없이 기존 지층을 사용한다. 표면 규칙 입력에 수평 보간을 추가하지 않으며, 지형 형상을 만드는 기존4블록 밀도/높이 보간은 유지한다.
- 컬럼 생성 작업의32청크는 같은 타일을 재사용하며 단독 청크 생성도 동일한 타일 계산 경로를 사용한다. 재질 함수와 균일 돌 청크의 빠른 경로가 모두 같은 모래 여부를 참조해 세로 청크 경계를 넘어 흙2층까지 유지한다. 좌표 canonical 처리와 기존 주기 노이즈로 X/Z 순환을 유지한다. 편집 후 표면을 다시 잔디/모래로 바꾸는 기능은 추가하지 않는다.
- 조건은 `assign_surface_rules`의 상수이며 이번에는 F8/JSON 필드를 추가하지 않는다. 저장된 worldgen, 지형 프리셋, 기후, 물 높이, 조명/AO는 수정하지 않았다. 이후 승인된 빌드로 실행한 뒤 새 월드 생성/재생성에서 반영된다. 해변 폭·분포와 성능은 아직 실행으로 확인하지 않았다.

## C/E별 PV 완전 제외 구간 (2026-09-21, 소스·현재저장 반영/미빌드)

- 사용자 최종 정정은 PV 계곡깊이를조절하는수준이아닌일부C/E구역에서PV영향전체를0으로하는것이다. `실시`로 능선프리셋과현재저장표의offset/factor/jaggedness모두W/PV독립상수칸으로변경했다. 아래 이전설명의모든지역중심강보호는해제되며PV제외구역에서는강후보자체를따르지않는다. 원본/다채로운내륙프리셋과배포default.json은이번에변경하지않았다.
- `terrain_presets.cpp::regional_pv_influence`를ridged프리셋작성마지막에적용한다. 각표C축끝이.25또는1미만이면그좌표행을기존마지막행복제로추가한다. 현재factor축끝.06에서.25/1행이추가되어변경지역이해안쪽으로상수외삽되는것을막는다. 원래표의무한대쪽상수연장이므로수정전함수는동일하다.
- C>=.25인행에서E∈[-.4,-.1]또는E>=.4인각칸을상수노드로교체한다. 그값은수정전표를W=-.45,+.45(PV=.35)의사면에서평가한평균이다. W=0계곡값을사용하지않아고원높이를강바닥으로고정하지않는다. 모든빈칸도상수로채워다른W종속칸이그사이로보간되지않게한다. 기준표복사본으로모든상수를계산하여수정순서에의존하지않는다. Jaggedness는상수0강제가아니므로PV와무관한작은굴곡은남을수있다.

- F8 `다채로운 내륙 스플라인 프리셋 불러오기`는 초안의 offset/factor/jaggedness 세 표만 교체하고 splines.enabled를 켠다. 현재 시드, 모든 노이즈/기후, height_scale, jagged_scale/jagged_enabled, shape/진폭/전체 squash는 유지한다. 원본 기반의 정해진 표를 매번 가져오므로 누적 적용이 아니다. 저장 파일은 직접 수정하지 않고 재생성/기본값 저장을 기존처럼 사용한다. 현재 사용자가 저장한 height_scale256과 노이즈 간격 등은 이 버튼으로 초기화하지 않는다.
- 원본 표의 각 정의된 칸을 Weirdness 외부 곡선으로 감싼다. 각 제어점의 자식은 원본 중첩 함수를 통째로 보존한 affine 변형이다. 출력 상수는 scale*value+shift, 모든 내부 접선은 scale*derivative로 바꾼다. 고정 W에서 원본 출력을 상수로 찍어 놓는 근사와 구별한다. 기존 C/E 빈칸 보간도 유지한다.
- 외부 W 위치는 [-1.3,-1.12,-.8,-.55,-.32,-.16,-.08,.08,.16,.30,.48,.7,1.1,1.3], 변형량은 [0,.6,1,.8,.55,.12,0,0,.18,.85,1,1,.4,0]이다. 접선은0이며 |W|<=.08 (PV<=-.76인 중심 계곡 구간)에서는 offset/factor/jaggedness 모두 원본 함수를 유지한다. |W|>=1.3도 원본으로 돌아간다. 중간 계곡 경사는 바뀔 수 있다. 기존에 사용자가 직접 편집한 표의 강 모양을 보존한다는 뜻은 아니며, 이 프리셋은 원본 표 기준이다.
- C 각 행의 변형 가중치는 smoothstep(-.1,.25,C)다. offset에서 C<=-.1은 그대로이며 이후 원래 행 보간으로 내륙 변화가 서서히 커진다. factor/jaggedness도 같은 C 가중치를 사용한다. 강 보호 구간의 세 표가 모두 원본이므로 같은 노이즈/배율에서 중심 수직 밀도도 보존된다. 실제 블록4격자 보간 때문에 경계의 표본은 인접 경사 변화 영향을 받을 수 있다.
- 지역별 제어값 (E,높이shift,원본높이relief,압축배율,잔굴곡추가)은 (-1/.85/1.15/.65/.22),(-.4/.85/1.15/.65/.22),(-.1/.48/.30/1.40/.015),(.2/.20/.85/.95/.035),(.4/.02/.45/1.80/0),(1/0/.35/2/0)이다. 이 값을 E로 smoothstep 보간해 각 원본 E열에 적용한다. 높이 shift는 정규화된 offset 단위여서 실제 블록 변화는 사용자의 height_scale에 비례한다. 음수 W 쪽 shift는65%로 줄여 양쪽을 다르게 한다. plateau는 원본 높이 변화량을 줄이고 전체 기준을 올려 넓은 고원을 지향하며 원본 높이를 완전히 상수로 만들지는 않는다.
- jaggedness는 원본 E축 끝-.375 이후 -.1/.2/.4/1 열을 추가한다. 각 행 마지막 정의값의 상수 E연장으로 시작해 원본 평가를 보존한 뒤 변형한다. 원본의 극단적 E에서만 나타나던 잔굴곡을 중앙 구간에도 약하게 배치한다. E<-.25는 원본 jaggedness1.35배, 나머지는.3배 방향으로 변형량에 따라 혼합한다. jagged OFF를 사용 중이면 켜지지 않는다.
- 예상 노드3727/최대 깊이3으로 기존16384/8 제한 안이다. 배열을 추가하는 것은 프리셋을 읽을 때뿐이며 worker에서 별도 authoring 계산을 하지 않는다. 다만 기존보다 트리가 커져 표 평가/초안 복사/JSON 크기는 증가한다. 실제 성능은 미측정이며 기존4블록 격자 계산을 유지한다.
- 아직 빌드/실행/시각적 비교는 하지 않았다. 중앙값 근처 W±.16~.48, E-.4~.4에 전환을 두었으나 실제 시드별 노이즈 분포를 측정한 것은 아니다. 기본값 저장 전 인게임 지도와 지형으로 비교 후 추가 튜닝해야 한다.

## 근거리 우선 스트리밍과 공개 순서 (2026-09-21, 소스 반영·미빌드)

사용자가 이동 중 먼 컬럼이 먼저 나타나며 외곽에 격자 같은 빈틈이 생긴다고 보고했고, 생성부터 공개까지 근거리 우선으로 변경하는 제안을 `실시`로 승인했다. 아래 이전 FIFO 예약/완료 즉시 공개 설명보다 이 절을 우선한다.

- 거리 기준은 플레이어가 속한 현재 컬럼 중심이며 X/Z `column_delta`의 순환 최단거리 제곱이다. 같은 거리는 canonical X/Z로 결정적인 순서를 사용한다. 플레이어 컬럼 이동/렌더 반경 변경 때 모든 미공개 컬럼 순서와 대기 작업 heap을 다시 계산한다. 매 프레임 정렬하거나 공개된 컬럼 전체를 다시 정렬하지 않는다. 로딩 원형 범위의 scanline 차집합 갱신은 유지한다.
- `WorldStream::tasks_`는 FIFO deque에서 우선순위 heap으로 변경했다. 블록 데이터/컬럼 내부 조명은 자신을 필요로 하는 미전달 렌더 컬럼 중 가장 가까운 컬럼의 우선순위를 상속한다. 외곽 halo도 포함한다. 같은 대상 우선순위에서는 메시→경계 조명→내부 조명→블록 데이터 순으로 진행된 단계를 먼저 처리한다. 위치 변경 시 queued data 우선순위를 갱신하고 heap을 재구성하며, worker가 후속 data 작업을 넣을 때도 현재 우선순위를 계산한다.
- `delivery_`의 가장 가까운 미전달8컬럼을 작업 대상으로 예약한다. 데이터가 아직 없는 근거리 컬럼도 이 범위에 포함해 먼 컬럼들이 메시 준비 자리를 전부 선점하지 못하게 한다. `schedule_dirty_` 이벤트로 worker가 이8컬럼만 재검토하고 경계 조명→32청크 메시를 예약한다. CPU active 최대8은 완료 즉시 반환하며 main 전달/화면 공개와 분리했다.
- 이동으로8컬럼 작업 범위 밖이 된 active/완료 메시 결과는 취소·해제하고 블록/내부 조명 데이터는 보존한다. 작업 revision을 증가시켜 이미 실행 중인 이전 경계 조명/메시 결과를 배제한다. 작업 단위 내부의 계산은 끝날 수 있지만 뒤늦은 결과는 새 예약을 건드릴 수 없다. queued 취소 작업은 요청 갱신 때 heap에서 제거하며 폐기한 큰 결과의 소멸은 scheduler mutex 밖에서 수행한다. 반복 이동 시 먼 완료 메시를 무한히 쌓지 않는다.
- `take_ready()`는 delivery의 첫 컬럼만 반환한다. 첫 컬럼이 미완료이면 뒤의 완료 컬럼을 건너뛰어 반환하지 않는다. 아직 공개되지 않은 컬럼은 별도 `publication_`에 남긴다. `next_to_publish()/publish()`는 현재 가장 가까운 컬럼만 공개 승인한다. pending 계측은 CPU 완료/전달이 아닌 실제 공개 또는 범위 이탈 때 감소한다.
- GPU 전송은 기존 프레임 예산/worker packing/한 컬럼 incoming 구조를 유지한다. 전송 중 이동해서 순서가 바뀌더라도 진행 중인 전송을 마치고 `Resident.published=false`로 보관한다. 이후 새 근거리 컬럼의 전송을 진행하므로 먼 incoming을 그대로 붙잡고 공개만 기다리는 교착을 피한다.
- `WorldView::publish_columns()`는 현재 공개 선두가 GPU resident이고 편집 메시·면 밝기·조명 갱신까지 끝나면 컬럼32청크를 함께 공개한다(프레임 최대8컬럼). hidden resident는 그리지 않고 loaded_block에도 제공하지 않아 표적/걷기에서 미공개 블록을 노출하지 않는다. hidden도 이웃 편집/조명 갱신과 범위 이탈 시 자원 회수 대상이며 메모리 계측에 포함한다. F3 visible은 공개된 수, pending은 공개 대기 전체다.
- 이미 공개된 컬럼은 이동으로 재숨김하지 않는다. 새 공개 순서에 대한 보장이며 이동 시 모든 렌더 범위가 항상 꽉 차 있다는 의미는 아니다. 느린 근거리 컬럼 때문에 먼 새 컬럼의 등장도 기다릴 수 있다. 우선순위 갱신 비용은 대기량에 비례하며 실행 성능/시각적 개선은 아직 검증하지 않았다.
- 청크 독립 생성, 컬럼 내부/이웃 경계 조명, 컬럼 동시 공개, 편집 청크 우선 갱신, 프레임 업로드 예산과 월드 순환은 유지한다. 빌드/게임 실행/자동 테스트는 수행하지 않는다.

## Snowcapped식 다변수 스플라인과 jaggedness (2026-09-20, 소스 반영·미빌드)

이 절은 아래의 v4 자체 지형 조합을 새 기본 프리셋에서 대체한다. 사용자 요청은 편집 UI뿐 아니라 인게임 지형 생성의 모방이며, jaggedness 추가 후 `실시`로 승인됐다. 기존 사용자 파일은 덮어쓰지 않는다.

### 저장 구조와 평가

- `terrain_spline.*`의 `SplineGrid`는 Groundness(C) × Smoothness(E)의 희소 표다. 각 칸은 상수 또는 Weirdness(W)/PV를 입력으로 하는 재귀 Hermite 스플라인이다. 자식 출력도 스플라인이 될 수 있다. C/E는 이웃한 정의된 행/칸 사이 smoothstep 보간, 표 바깥은 가장 가까운 값이다. W/PV는 저장된 접선으로 cubic Hermite 보간하고 양 끝은 접선으로 선형 연장한다. 원본 C/E 접선은 모두0이다.
- `PV = 1 - abs(3*abs(W)-2)`이며 새 모드는 이 단계에서 clamp하지 않는다. 원본 Snowcapped 자료의 `ridges`는 PV, `weirdness`는 W다. 최신 Minecraft JSON의 명칭과 혼동하지 않는다.
- `TerrainSplines`는 offset/factor/jaggedness 표와 켜짐, 높이 배율, 잔굴곡 배율/켜짐을 가진다. `GenerationConfig.jagged`는 별도의 주기적 2D Perlin 세부 노이즈다. jaggedness 자체는 독립 난수 지도가 아니라 C/E/W/PV의 함수다.
- JSON schema5: 각 표에 `groundness`, `smoothness`, 행 우선 `cells`를 저장한다. 빈 칸은 null, 상수는 숫자, 곡선은 `axis`와 `points[{location,derivative,value}]`다. 파일 최대4MiB, 축1..24개(-2..2), 곡선 점1..64개, 간격>=0.0001, 전체16384노드/깊이8, 상수·기울기 절댓값<=64를 검증한다. 모든 표에 최소1칸이 필요하다. 저장 크기도 검사하고 기존 원자적 교체를 유지한다.
- v1..4를 읽으면 `splines.enabled=false`로 이전 지형 수식을 유지한다. v1..3은 기존 groundness-only, v4는 아래의 자체 조합이다. F8의 `원본 스플라인 초기 프리셋 불러오기`가 새 모드 전환점이다. 현재 시드·기후는 보존하고 재생성/저장은 사용자가 별도로 누른다.

### 실제 지형 수식

- `base_height = 192 + height_scale * offset(C,E,W)`; 초기 height_scale=128. 원본 offset 수치와 높이 스케일을 유지하면서 기준점을 우리 해수면192로 옮겼다. Minecraft의 별도 -0.50375 offset 상수와 절대 Y좌표를 그대로 사용하는 것은 아니다.
- `detail = jagged_noise < 0 ? jagged_noise/2 : jagged_noise`; `height = clamp(base_height + jagged_scale * clamp(jaggedness,0,64) * detail,0,512)`. 초기 jagged_scale=128. 잔굴곡 OFF 또는 배율0이면 해당 노이즈 계산을 생략한다.
- `local_squash = squash * clamp(factor(C,E,W),0.01,64)`; `gradient = local_squash * (height-(y+0.5))`; `density = amplitude*shape + (gradient>0 ? 4*gradient : gradient)`. 원본 sloped_cheese의 `4*quarter_negative` 방향을 반영했다. 진폭32/shape의 주기적 3D Perlin 및 세로 간격48은 기존 구현이다. 원본 blended-noise 전체와 동굴/대수층은 구현하지 않았다.
- 새 모드에서는 이전 river_width/depth 절삭 수식을 호출하지 않는다. 계곡/강바닥은 offset 트리에 포함된다. 물은 기존대로 빈 셀 y<192다. 모든 시드·튜닝에서 수로 연결성이나 수심을 보장하지 않는다.
- 높이/압축/잔굴곡은 컬럼의4블록 정렬 격자에서 계산해 쌍선형 보간하고, shape는4블록 3D 격자를 삼선형 보간한다. 높이와 압축을 보간한 뒤 밀도를 합성한다. 지표 탐색과 청크 생성이 같은 `density()`를 호출한다. 3D OFF는 잔굴곡을 포함한 2D 높이를 사용한다.
- 보수적 공기/고체 판별 및 지표 검색 상한은 각 보간된 위치의 `2*amplitude/local_squash`를 사용한다. 양수 gradient 강화는 이 범위를 확대하지 않는다. 전역 최소 factor 때문에 불필요하게 전체 높이를 검색하지 않는다. 기후 신호는 지형 경로에서 읽지 않는다.

### 초기 자료와 노이즈 조정

- Snowcapped 고정커밋 `b16f532359d82ddb17cd0911a5d1420cb7560986`의 vanilla offset/factor/jaggedness를 가져왔다. 제어점/상수/접선은 원본 그대로, 자료 구조만 변환했다. offset10×11/48칸/248노드, factor5×13/42칸/130노드, jaggedness3×4/9칸/41노드다. 상세 출처와 자료 권리 구분은 `assets/worldgen/NOTICE.md`.
- 가져오기 도구 `tools/import-terrain-preset.py`가 `assets/worldgen/default.json`과 `src/world/terrain_preset.inc`를 함께 생성한다. 코드 fallback과 에셋 프리셋의 표를 일치시킨다. 의존성 빌드나 실행 시 다운로드는 없다.
- groundness spacing_log2=11/9옥타브, smoothness=11/5옥타브, weirdness=9/6옥타브. Minecraft continentalness/erosion/ridge의 옥타브 amplitude 목록에 0.5^i를 곱해 정규화 가중치로 옮겼다. 0가중치 옥타브는 SIMD 계산을 건너뛴다. 표본 노이즈는 우리 periodic Perlin이며 원본 NormalNoise의 두 Perlin 합/좌표 이동/seed 해싱과 같지 않다.
- 원본 jagged는 firstOctave=-16,16겹,xz_scale1500이다. 프로젝트는 2의 거듭제곱 간격과 최솟값4블록 제약에 맞춰 spacing64/5겹/gain0.5로 시작한다. 동일한 원본 주파수/옥타브 구성이라고 보고하지 않는다.
- 모든 신호에 선택적 명시 weights를 지원한다. 비어 있으면 gain 재귀 가중치, 명시 가중치는 가중합/전체 합이며 전체0이면0이다. 저장은 weights와 전환 복원용 gain을 함께 지원한다. 2D 최대16옥타브이며 가장 작은 간격4블록, 3D UI는8옥타브까지(세로 최솟값 제한도 적용). 기존3D gain 재귀의 float 가중치 순서를 유지한다.

### 편집/미리보기

- F8에서 새 모드의 높이 배율, 잔굴곡 ON/OFF·배율·노이즈와 표 창을 연다. 구형 단일 높이곡선/river 제어는 구형 모드에서만 보인다. 표는 행/열 추가·삭제·좌표 수정, 칸 복사/붙여넣기/비우기, 재귀 곡선 축·점·기울기 편집과 W 단면 그래프를 제공한다. 숫자는 Ctrl+클릭 입력이다. 빈 칸을 채울 때 현재 W 단면의 보간값으로 상수를 만든다. 새 곡선 점도 상수 출력/0접선이므로 곡선 전체를 불변 유지하는 분할 연산은 아니다.
- 지도12종: groundness/smoothness/weirdness/PV/잔굴곡 전 기준 높이/온도/강수량/offset/최종 압축/jaggedness/잔굴곡 원본/잔굴곡 적용 높이. 마지막 높이는 실제 생성의 `profile()`과 같은 수식, 지도 표본 자체에는 블록의4블록 보간/3D 지표 탐색을 적용하지 않는다. 넓은 지도에서 세부 노이즈 aliasing이 가능하므로 범위를 좁혀 본다.
- factor 흑백0..8(전체 squash 포함), jaggedness0..1(스위치/배율 적용 전), 노이즈·offset -1..1, 높이는 기존 해수면 색상이다. 실제 표본값/min/max는 색상 clamp와 독립이다. 구형 모드에서 offset/jaggedness는0으로 표시하고 안내한다.
- 미리보기/편집/저장은 기존 비동기/재생성/기본값 저장 규칙을 따른다. 청크 독립성, 컬럼 동시 공개, 해수면192, 월드512/131072, 온도 띠, 기후 독립성을 유지한다. 별도 빌드·자동 테스트 추가는 승인되지 않았다.

## 다중 지형 지도와 기후 (2026-09-20, 소스 반영·미빌드)

이 절이 이전 groundness/shape 두 신호·고정 squash·강 없음·구형 초기값 설명을 대체한다. Minecraft의 대륙성/침식/봉우리·계곡 개념을 참고한 프로젝트 고유 조합이며 Mojang의 전체 스플라인 트리를 그대로 복제하지 않는다. 식생·바이옴 배치·domain warp·대수층·LOD·물 흐름은 추가하지 않았다.

- `GenerationConfig`에 groundness, smoothness, weirdness, shape, temperature, precipitation과 지형 곡선/기후 띠 설정을 모았다. FastNoise2 SIMD 주기적 Perlin 확장을 유지한다. 지형 지도와 강수량은 X/Z 주기131072, shape는 X/Z만 주기적이다. temperature 원본2D만 Z 격자 마스크를 끄고 X만 주기적이다. upstream은 수정하지 않는다.
- groundness→PCHIP 높이가 대륙 기본 틀이다. smoothness→PCHIP(0..1)은 PV 지형의 세기를 조절하며 초기 곡선은 smoothness가 높을수록 약해진다. `PV=clamp(1-abs(3*abs(weirdness)-2),-1,1)`이고 별도 PV→PCHIP 기준 높이를 편집한다. 기본 높이176~216에서 부드럽게 증가하는 내륙 가중치를 곱해 산악 높이를 합성한다. 초기 기본 높이곡선/격자값은 `assets/worldgen/default.json`과 코드 기본값에 일치시켰다.
- PV=-1 부근의 강 중심과 넓은 계곡을 높이 합성 단계에서 만든다. 바닥 목표는 `min(대륙 높이,192-river_depth)`이며 강 중심/계곡 폭은 PV 값 구간 단위다(블록 단위 아님). 해안의 높은 둑을 줄이는 보정도 포함한다. 별도 가변 수면 없이 빈 셀 y<192만 물이다. 수문학적 연결이나 모든 파라미터에서 강에 물이 있는 결과를 보장하지 않는다.
- 최종 압축은 기본 squash×지역 배율이다. smoothness -1..1에서 rough_squash→smooth_squash를 보간하고 강 중심은 최소 river_squash까지 높인다. 최종 밀도는 `amplitude*shape + local_squash*(height-(y+0.5))`. 기존 고체 판정·수중 모래3/흙2·육지 잔디/흙3·나머지 돌을 유지한다.
- 4블록 정렬 격자25점에서 높이와 압축을 계산하고 각각 쌍선형 보간하여 TerrainSite에 보관한다. shape125점 삼선형 보간은 유지한다. 최고 고체 검색과 블록 생성이 같은 local_squash를 사용한다. 청크는 이웃 데이터 없이 독립 생성 가능하며 컬럼 생성 경로는 tile을 공유한다. 깊은/높은 uniform 생략의 보수적 범위는 최소 압축 배율을 고려한다.
- `terrain.enabled=false`는 예전 groundness 높이/상수 squash 동작이다. shape_enabled=false는 shape 계산을 생략하되 켜진 지형 조합은 유지한다. 두 옵션을 모두 끄면 groundness 높이만 남는다.
- temperature/precipitation은 `TerrainGenerator::map`으로 필요할 때만 샘플링한다. 지형 profile/밀도/블록 생성은 두 기후 값을 읽거나 계산하지 않는다. 현재 바이옴 데이터 저장/배치는 없다. 기후 설정도 생성 서명에 포함하므로 설정이 다른 tile 재사용은 금지한다.
- temperature는 canonical Z에서 `latitude=(1-cos(2*pi*z/131072))/2`, `belt=latitude^latitude_power`, `warmth=clamp(belt+raw*variation*belt*(1-belt),0,1)`, 최종 `lerp(poles,equator,warmth)`다. Z65536 적도와 Z0/131072 한랭대에서 노이즈 영향은0이며 양 끝 값/기울기가 이어진다. 원본 노이즈는 Z 반복이 아니지만 최종 월드 경계는 연결된다. 지역 편차가 있으므로 모든 국소 구간의 엄격한 단조 온도 상승은 뜻하지 않는다. 섭씨가 아닌 -1..1 지수다. 강수량은 독립 fBm 원신호이며 표시 색만 -1..1로 제한한다.
- JSON schema4는 새 지도/terrain/temperature_bands를 저장한다. v1..3은 terrain.enabled=false와 새 기후 기본값으로 읽어 기존 지형 설정을 유지한다. 사용자의 실행 파일 옆 worldgen.json은 변경하지 않았다. 배포 default.json만 새 초기 프리셋으로 갱신했다. F8의 새 지형 초기 프리셋 버튼은 초안의 지형값만 교체하며 시드·기후 설정을 유지한다. 실제 적용/저장은 기존 재생성/기본값 저장 버튼을 따른다.
- F8에서 smoothness/PV 곡선은 점별 입력/출력 수치, 내부 점 삭제/추가, PCHIP 그래프를 제공한다. 원래 groundness 드래그 그래프는 유지한다. 지도 미리보기는 groundness/smoothness/weirdness/PV/3D 적용 전 높이/temperature/precipitation을 제공한다. 온도·강수량 선택 시 전체 월드(0..131072) 범위, 색상 범례, 이미지 좌표/값, 수동 범위/해상도, 비동기 취소를 지원한다. 개별 옥타브/가중치 보기는 groundness만 지원한다. 높이 미리보기는 연속 profile의 표본이며 4블록 보간 후 블록 표면과 완전히 같지는 않다.
- 실제 지형/강의 시각적 품질, UI 배치, 생성 비용은 실행 확인 전이다. 초기값은 조정 출발점이다.

## F2 스크린샷 / 과거 F4 와이어프레임 (역사 기록)

2026-09-26 후속실시로 와이어프레임은제거했다. 현재F4는 [LOD단계표시](lod-2026-09-26.md)의단색·외곽선보기다. 아래선화구현은과거이력이며현재코드에없다.

- 사용자 `실시` 승인. F2는 메뉴/월드 공통, F4는 플레이 중에만 작동한다. KEY_DOWN의 repeat를 제외하며 F4 상태는 WorldView에 두어 메뉴 왕복·청크 편집·렌더 거리 변경에도 유지한다.
- F4는 동일 32비트 면 SSBO를 읽고 실제 삼각형 정점 번호를 12개 선 끝점으로 변환한다. AO 대각선 flip과 음의 면 winding을 그대로 적용한다. 별도 메시 재생성/업로드와 추가 장치 feature는 없다. specialization constant 0을 vertex/fragment 양쪽에서 켠 LINE_LIST 파이프라인이며 fragment는 텍스처/AO 샘플 없이 밝은 선(대상 블록은 노란 선)을 출력한다. 물도 같은 패스로 합쳐 그리며 depth test/write ON, blend OFF, cull NONE이다. 채움이나 hidden-surface 깊이 선행 패스는 없으므로 표면 사이로 뒤쪽의 노출 면 선들도 보인다. 원래 메시에 없는 내부 면은 만들지 않는다. F3 triangles는 원본 메시의 논리적 삼각형 수다.
- F2 경로는 UTF-8 SDL_GetBasePath에서 만든 절대 경로 `screenshots/`다. 로컬 시각 `YYYY-MM-DD_HH-MM-SS_mmm.png`, 이미 있으면 `_1` 등의 접미사로 기존 파일을 보존한다. 프레임 취득이 resize/최소화로 생략되면 요청을 다음 프레임까지 유지한다. 한 프레임 안의 여러 요청은 하나로 합친다.
- 월드와 RmlUi/ImGui를 모두 그린 뒤 스왑체인을 읽는다. 기존 동기식 GPU readback/PNG 인코딩이므로 촬영 프레임은 지연될 수 있다. 평소 프레임에는 readback 비용이 없다. BGRA를 RGBA로 변환하고 PNG alpha를 255로 저장한다. ofstream(path) + stb callback으로 한글 Windows 디렉토리도 처리한다.
- 파일/폴더/PNG 저장 실패는 로그 및 5초 RmlUi 알림으로 전달하고 게임을 계속한다. 저장 알림은 캡처 뒤 다음 프레임부터 보인다. 알림 문서는 focus를 받지 않고 pointer-events:none이다. GPU 오류는 기존 오류 경로를 따른다. CLI `--capture` 실패는 여전히 실행 실패이며 같은 프레임에서는 CLI 요청을 우선한다. screenshots 폴더는 Git 제외다.

## 순환 좌표와 생성 설정

- X/Z 주기 131072블록(8192컬럼), Y=0..511 비순환. 블록 좌표의 floor 분해는 유지하고 저장/요청/이웃 키만 `canonical()`로 0..8191에 정규화한다. circle 반경·작업 우선순위는 `column_delta`, 그리기/프러스텀/물 정렬은 카메라에 가장 가까운 `world_delta` 위치를 사용한다. 카메라는 double이며 경계 통과 시 0..131072로 감싼다.
- 기본 데이터, 27개 이웃 snapshot, data-only 링, 편집 맵, dirty 청크, ray sample과 대상 테두리가 같은 키 규칙을 사용한다. ray 자체는 가까운 연속 좌표로 진행하고 조회에서 감싸므로 경계 너머에도 사거리 6을 그대로 적용한다. 동일 청크를 좌우에 별도 데이터로 만들지 않는다.
- `GenerationConfig`에 시드, groundness/shape 설정, Y 스케일, 진폭, squash, 그래프를 모은다. `TerrainGenerator`는 생성 시 검증하고 FastNoise2 노드와 곡선 기울기를 준비하여 worker가 불변 공유한다. 순서/이웃/가변 난수 상태에 의존하지 않는다.
- `assets/worldgen/default.json`은 배포 기본값, 실행 파일 옆 `worldgen.json`은 사용자가 F8로 저장한 우선 기본값이다. 후자는 빌드/패키징으로 덮어쓰지 않는다. 재실행 때 우선 파일→배포 기본→코드 초기값 순으로 사용한다. 잘못된 파일은 덮어쓰지 않고 오류를 로그와 편집창에 알린다. `--seed`는 이 실행의 시드만 덮어쓰며 F8에서 저장하면 그 값도 포함된다.
- JSON은 world_size 고정값을 검사한다. 범위 밖/비유한 값, 소수인 정수 파라미터, 중복/비정렬 곡선 X를 거부한다. 64KiB 제한, UTF-8 텍스트, Windows 유니코드 경로를 지원한다. 저장은 형제 `.tmp`를 정상 close한 뒤 MoveFileExW의 replace/write-through로 교체한다. 실패 시 기존 기본값은 보존한다. 블록 편집을 파일로 저장하는 기능은 여전히 없다.

## 생성 함수와 보간

- FastNoise2 v1.1.1와 해당 FastSIMD 커밋을 lock으로 고정했다. 프로젝트의 `cmake/fastnoise`는 pinned 로컬 소스만 사용하고 upstream CPM 다운로드를 호출하지 않는다. upstream 파일은 변경하지 않는다. `periodic_perlin.inl`은 원본 Perlin 커널(MIT)을 확장하여 각 격자 모서리의 X/Z 정수 좌표를 prime 곱 이전에 마스킹한다. 2D의 두 번째 축은 월드 Z다. 3D Y에는 마스크를 씌우지 않는다. 5D 토러스 매핑을 사용하지 않는다.
- FastSIMD가 지원 CPU 경로를 선택하며 RELAXED SIMD/FMA를 허용한다. strict FP 일치나 SIMD별 비트 일치를 요구하지 않는다. 실제 처리량은 미측정이다. 단일 점 호출 대신 `GenPositionArray2D/3D`로 25/125점 묶음을 계산한다.
- fBm은 동일 SIMD 커널 안에서 octave를 누적한다. octave마다 좌표·격자 period를 2배, seed를 +1 한다. groundness는 개별 가중치, shape는 기존 gain의 거듭제곱 가중치를 사용한다. 모든 octave의 물리적 주기는 world_size다. 비음수 가중치의 합으로 정규화하며(모두0인 groundness는0) FN 기본 출력 스케일을 사용한다(명목 범위 -1..1, 별도 noise clamp/0..1 변환 없음).
- X/Z 기본 격자 간격은 `2^spacing_log2`, 지수2..17(4..131072블록). octave1..min(8, spacing_log2-1), gain0..1, seed_offset은 int32다. 가장 촘촘한 octave도 가로4블록 이상을 유지한다. Y 기본간격은 4×2^(shape.octaves-1)..4096블록이다. 임의 실수 가로 주파수는 주기를 깨므로 제공하지 않는다. octave 주파수 배율2는 고정한다.
- groundness는 periodic 2D Perlin fBm. 기본 지수10(1024블록), 4octaves, 가중치[1,0.5,0.25,0.125], offset0. 그 출력을 PCHIP 곡선으로 base_height에 매핑한다. 그래프 X는 -1..1, Y는0..512, 양끝 X고정, 2..32점, X최소간격0.001. 각 구간이 두 끝점 높이를 벗어나지 않으며 올라갔다 내려가는 비단조 곡선도 가능하다. 범위 밖 입력은 끝점 높이로 연장한다. 초기 점은 (-1,100),(-0.3,175),(0,205),(0.5,280),(1,400)이며 시각적 품질은 아직 검증하지 않았다.
- shape는 periodic 3D Perlin fBm. 기본 가로64, 세로48블록, 2octaves, gain0.5, offset16883, amplitude32, squash1. 진폭0..512, squash0.01..64를 편집한다. 밀도는 `amplitude*N + squash*(base_height - (y+0.5))`. 양수면 고체(아래 표면 재질 규칙 적용), 나머지는 y<192 물/그 위 공기. squash 값이 클수록 같은 진폭에서 입체 변형의 수직 범위가 좁아진다. 별도 압축 맵/warp/강은 없다.
- 4블록 정렬 격자에서 groundness→높이를 계산하고 블록 중심 높이를 쌍선형 보간한다. 컬럼별 TerrainTile이 256개 base_height와 최고 고체 surface_y를 보관하여 세로32청크가 공유한다. optional tile 없이 같은 시드/설정/좌표로 독립 생성해도 결과가 같다. tile의 canonical 키/시드/config fingerprint 불일치는 거부한다.
- 각 혼합 청크는 5³=125점의 shape를 계산하고 블록 중심에서 삼선형 보간한다. 매 블록 노이즈 호출은 하지 않는다. 표면 재질은 아래 규칙을 따르며 놓기 슬롯의 흙/잔디/돌은 유지한다.
- 깊은 돌/높은 공기·물은 보수적 범위로 3D 계산을 생략한다. 3D gradient dot은 두 offset합이고 FN bounding은1보다 커서 보수적 |N|<2를 사용한다. 수직 상한폭은 `2*amplitude/squash`, 노이즈에 clamp를 추가하지 않는다. 기타 결과도 모두 같으면 uniform으로 압축한다.
- 최초 월드 진입 시에만 보수적 지형 상한(최대512)·수면 중 높은 곳보다28블록 위에 카메라를 둔다. 재생성은 플레이어 위치 X/Y/Z와 카메라 yaw/pitch를 변경하지 않는다. 새 지형 내부에 겹쳐도 자동으로 이동시키지 않으며 선택 슬롯/F4도 유지한다. 기존 uint32 seed 편의 API는 독립 호출용이며 hot path는 불변 TerrainGenerator를 재사용한다.

## F8 편집과 재생성

- F8은 인게임 생성 편집창만 열고 닫는다. F3는 독립된 좌상단 진단 텍스트 표시/숨김이며 조작을 차단하지 않는다. 생성 편집창은 한글 항목 이름과 hover 도움말을 사용한다. 시드, 두 노이즈의 격자/옥타브/게인/오프셋, 높이 곡선, 세로 간격, 진폭, 압축 강도 및 편집/저장 버튼의 의미를 설명한다. 진단 수치는 F3 텍스트 오버레이에서 따로 제공한다. 편집창이 열리면 상대 마우스 캡처를 해제하고 이동/블록 편집을 차단한다. Esc 옵션은 더 높은 입력 우선순위를 갖는다.
- 그래프 제어점을 드래그/숫자로 조절하고 빈 곳 더블클릭 또는 중간 점 추가로 추가, 내부 점 삭제가 가능하다. 높이축 0..512, groundness축 -1..1, 파란선 해수면192다. 초기/최소 창에서 길어지는 편집 내용은 창 내부 스크롤로 접근한다.
- 초안은 노드에 바로 쓰지 않는다. 재생성를 누르면 다음 프레임 begin_frame 전에 새 노드/stream을 준비하고 기존 stream을 취소·join한다. old ready/upload/resident/dirty/edits/target 상태를 제거하며 GPU buffers/descriptor는 마지막 제출 완료 후 지연 폐기한다. 파이프라인과 아틀라스는 재사용한다. 이후 컬럼 공개 규칙대로 새 월드를 로딩한다.
- 기본값 저장는 현재 초안을 저장하고 복사 가능한 JSON을 표시한다. 현재 월드를 자동 재생성하지 않는다. 편집 되돌리기는 현재 적용된 설정을 초안으로 복구한다. 재생성하면 현재 실행에서 변경한 블록은 모두 초기화된다. 저장과 재생성의 의미는 UI 도움말에도 명시한다.

## 바다와 물

- 강을 만들던 domain warp/영점 띠/폭 노이즈와 강·계곡 절삭 함수는 사용자 요청으로 제거했다. 기본 지형이 낮아서 생기는 좁은 수역은 남을 수 있지만 별도 물길을 생성하거나 깎지 않는다.
- 해수면은 기하학적 Y=192다. 밀도가 비어 있고 셀 y<192이면 물, 그 이상이면 공기를 배치한다. 최상단 물 블록 y=191의 윗면이 192다. 해수면 아래 빈 동굴도 물로 채워지는 단순 규칙이며 별도 대수층은 없다.
- `Block::water`는 solid/AO occluder가 아니다. 고체-물 경계는 고체 면을 유지하고, 물 면은 공기와 맞닿을 때만 만든다. 물-물/물-고체 내부 면은 만들지 않는다. 물을 통과해 고체를 선택할 수 있으며 놓기로 물 셀을 교체할 수 있다. 물 선택/양동이/흐름은 없다. 편집으로 만든 빈 셀도 자동으로 물이 차지 않는다.
- 물은 별도 CPU 면 목록에 저장하되 GPU에는 청크당 기존 SSBO에 고체 면 뒤로 이어 붙인다. 고체 수/전체 수를 구분하여 물 draw의 firstInstance를 고체 수로 지정한다. face ABI는 여전히 uint32 4바이트, 물 재질 인덱스는 5다.
- 월드 아틀라스는 192×32, water는 `assets/textures/fluid/water.png`다. 고체를 먼저 그리고 물 청크는 카메라 거리 역순으로 그린다. 물은 depth test ON, depth write OFF, 양면, SRC_ALPHA/ONE_MINUS_SRC_ALPHA이며 알파는 원본 알파×0.72다.
- 물 정렬은 청크 단위여서 교차하거나 겹치는 복잡한 물 표면의 정확한 투명 순서를 보장하지 않는다. 파동·반사·굴절·수중 안개는 아직 없다. 물의 시각 결과와 측면/수중 시점은 빌드 후 확인 대상이다.

## 데이터 준비와 메싱 스케줄

- WorldStream은 작업 스레드 1~4개(하드웨어 스레드 수/2 제한)를 사용한다. 작업은 컬럼 데이터 생성(표면 타일1개+32청크) → 컬럼 내부 조명 → 이웃 경계 전파 → 개별 청크 메싱으로 분리한다. 이 구조는 2026-09-20 승인으로 개별 청크 데이터 작업 예약을 대체한다. SDL/Vulkan은 메인 스레드 전용이다.
- 렌더 요청은 표시 플레이어 위치 중심 원형 반경(기본12, 1~64)이다. 데이터 요청은 이 원형의 모든 컬럼에 대해 x/z ±1을 합친 정확한 한 겹이다. 이 외곽 컬럼은 블록 데이터와 내부 조명을 만들지만 메시/그리기는 하지 않는다.
- 메싱은 자기 청크와 26방향 이웃 중 세계 높이 안에 있는 데이터가 모두 준비된 뒤만 예약한다. 작업 스레드는 이웃을 기다리는 작업을 실행하지 않는다. 컬럼 내부 조명이 완료되면 영향받는 주변9개 렌더 컬럼만 준비 여부를 재검사한다. 경계 조명이 끝난 컬럼은32개 메시 작업을 모두 등록한다.
- make_halo는 준비된 immutable ChunkNeighbours에서 18³ halo를 읽는다. 세계 높이 밖은 공기지만, 세계 안에서 데이터가 없으면 오류이며 절차 샘플링이나 공기 대체를 하지 않는다. 실제 편집 재메싱은 stream.halo가 아직 준비되지 않았으면 예약을 유지한다.
- Chunk의 혼합 블록 배열은 shared_ptr<const array>로 보관한다. 데이터 캐시/작업 스냅샷/공개 컬럼이 공유하고 수정 시 복사한다. CPU 블록 배열은 GPU 업로드 후에도 외곽 데이터와 함께 유지하여 이웃 판정에 재사용한다.
- 동시에 경계 조명/메시를 만들거나 완료 큐에 보관하는 컬럼은 합쳐 최대8개다. 소비자가 완료 컬럼을 가져오면 빈 자리에 다음 준비된 컬럼을 예약한다. 데이터 작업은 계속 실행할 수 있어 의존성 때문에 완료 큐와 서로 기다리는 교착이 없다. 전체 데이터 캐시는 요청 반경에 비례하므로 큰 반경 RAM 비용은 별도 측정해야 한다.
- 요청 범위 밖의 data/render 상태에 각각 취소 토큰을 설정하고 대기 작업/완료 큐를 소비할 때 취소 항목을 건너뛴다. 컬럼 블록 생성은 청크 사이에 취소를 확인하고, 실행 중인 조명/메시 작업은 끝난 뒤 토큰을 확인하고 결과를 버린다. 동일 좌표를 다시 요청해도 이전 토큰의 결과를 받지 않는다. 재생성된 데이터의 준비 순서는 결과에 영향을 주지 않는다.
- 생성/초기 조명/메시 시간은 각 작업의 wall time을 컬럼별로 합산한 값이다. 초기 조명 수치는 해당 컬럼 내부 계산과 경계 연결 작업의 합이며 이웃 내부 계산, 큐 대기, 편집 조명 재계산은 포함하지 않는다. 작업들이 겹칠 수 있으므로 컬럼의 실제 요청→완료 지연시간이나 단일 스레드 CPU 시간이라고 해석하지 않는다. pending은 아직 소비자가 받지 않은 렌더 컬럼 수이며 데이터 전용 링 수는 제외한다.

## 컬럼 공개와 편집

- 메인 스레드는 완료 컬럼을 하나씩 받아 청크별 GPU 업로드를 기록한다. 후속 로딩 개선으로 CPU 면 밝기 준비는 MeshLightWorker에서 수행하고 main의 실제 업로드는 프레임당 최대4청크/2MiB/2ms soft budget을 사용한다. 개별 청크는 마무리하며 현재 incoming 컬럼 하나를 완성한 뒤 다음 컬럼을 받는다. 32개 청크가 모두 업로드된 뒤 columns_에 삽입하여 한 번에 공개한다. 업로드 배리어는 vertex shader storage read다.
- WorldEdits는 메인 스레드의 컬럼별 희소 변경 맵이다. 원래 블록 값은 이미 생성된 immutable 데이터에서 받고, 원상복구하면 기록을 지운다. CPU worker는 편집 맵에 접근하지 않는다.
- 선택과 편집 메시는 기본 데이터에 변경 기록을 덮어쓴 실제 값으로 판단한다. 편집 재메시는 준비된 halo에 변경 기록을 적용한다. 이웃 데이터의 중복 생성/노이즈 계산은 없다.
- 변경한 블록 주변 1셀 halo와 겹치는 개별 청크만 dirty(최대8)로 표시한다. 공개 청크는 프레임당 최대4개/CPU2ms soft budget으로 재메싱하며 GPU 버퍼/descriptor는 fence까지 지연 해제한다. 청크별 갱신은 몇 프레임에 나뉠 수 있다.
- 컬럼을 처음 소비할 때 편집 영향을 받는 청크를 표시하고 업로드 직전에 재메싱한다. 업로드 중 이웃 편집이 발생하면 해당 청크만 완료 비트를 취소한다. 최신 32청크를 모두 올리기 전에는 공개하지 않는다.
- 메뉴 왕복, 범위 축소/확대, 멀리 갔다 돌아와도 세션 편집을 유지한다. 파일 저장은 없다. 좌클릭 파괴/우클릭 놓기, 1/2/3 흙/잔디/돌, 사거리6과 대상 테두리는 유지한다. 설정 조작 중에는 블록을 편집하지 않는다.

## 기존 렌더러와 다음 검증

- packed face 비트 0~11 xyz,12~13축,14방향,15~17재질,18~25 AO,26 대각선이다. 각 면은 6개 shader vertex로 확장한다. CPU 패킹과 GLSL을 함께 바꿔야 한다.
- AO는 바깥쪽 side2+corner1 점유를 사용한다. 두 side가 모두 차면0, 아니면3−s1−s2−corner다. 밝기는0.45~1.0, 대각선은 ao0+ao2 > ao1+ao3이면 바꾼다. 그리디 메싱은 없다.
- CPU 청크 AABB frustum culling, 고체 backface culling, D32 depth를 사용한다. 컬럼 공개와 별개로 보이지 않는 청크는 draw를 생략한다. GPU driven/occlusion culling/LOD는 없다.
- 카메라 위치는 double, GPU에는 카메라 상대 좌표를 보낸다. 좌표 보호 범위 X/Z ±10억, Y -512~4096을 유지한다. 수평 WASD는 yaw만, 시점과 선택 ray는 pitch를 포함한다. F11 borderless fullscreen과 F3 진단을 유지한다. Esc는 월드 위 어두운 옵션창을 열고 닫으며 Tab 설정 토글은 제거했다. 옵션창에서 렌더 거리, 게임으로 돌아가기, 시작 화면으로를 제공한다. 카메라/편집 입력은 paused로 차단하지만 prepare/render는 계속하여 거리 변경과 로딩을 즉시 반영한다. 플레이어 이동 누산은 게임 입력이 허용된 동안만 진행하므로 옵션/F8/메뉴/포커스 상실 동안의 경과 시간은 복귀 후 따라잡지 않는다.

## F8 그라운드니스 이미지 미리보기 (2026-09-13, 미빌드)

- GroundnessPreview는 GenerationEditor의 멤버이며Renderer를 참조한다. 요청은 버튼 클릭 시 GenerationConfig와PreviewRange를 복사한 스냅샷이다. 범위는 정수0≤시작<끝≤world_size를 양축에 적용하고 기본은0~16384다. 범위/이미지는 worldgen.json에 저장하지 않는다.
- worker는 한 jthread로 대기하며 요청 슬롯과 완료 슬롯은 각1개다. 새 요청의revision이 이전 요청을 취소하고 행마다 stop/revision을 확인한다. mutex는 슬롯 교환에만 사용한다. 계산/노이즈 graph와 배열은worker 소유이며 GPU/ImGui 접근은main에서만 한다. 숨긴 창에서도 계산 완료는 유지하고 종료는stop 요청 후join한다.
- 불변 TerrainGenerator의 groundness 배치 함수를 재사용한다. shape/height curve는 흑백값에 적용하지 않는다. 긴 축은256/512/1024/2048표본(기본512), 짧은 축은 비례해최소2표본이며 범위 양 끝을 포함해 샘플링한다. 좌표world_size는0으로wrap한다. 고정명암round(clamp((raw+1)/2,0,1)*255), alpha255다. 원시 float값과min/max를 유지하며 정규화된 대비 확대는 하지 않는다. 넓은 범위의 작은 특징은 다운샘플링되어 사라지거나 alias될 수 있다.
- 랜덤 시드는 UI 소유mt19937로 이전과 다른uint32 시드를 초안에 넣고 요청한다. 랜덤 위치는 시드/폭/높이를 유지하고 완전히 월드 안에 들어오는 범위로 이동한다. 둘 다 실제 월드 재생성/파일 저장 요청은 하지 않는다. 표시 이미지의 시드/groundness/range가 초안과 다르면 이전 이미지임을 알린다. 값/좌표 hover는 표시된 결과 스냅샷의 가까운 표본을 사용한다.
- prepare_preview는 renderer.begin_frame 성공 후, 모든 begin_rendering 이전에 결과를poll하고 새 RGBA texture를 업로드한다. Renderer::create_texture의staged=true 경로는현재command에 전송/fragment-read barrier를 기록하며 staging을defer한다. 기존 기본false 경로는기존 동기 업로드를 유지한다. CPU계산/UI요청은 렌더 thread를 기다리지 않고 미리보기 업로드도queue idle을 호출하지 않는다.
- ImGui sampled-image descriptor는 AddTexture로 별도 등록한다. 이전 이미지/descriptor는 완료표식이 충족된 프레임 이후main에서 정리한다. 완료 callback은 공유bool만 보유해 preview 파괴 이후에도 자원접근하지 않는다. 창크기 변경으로 ImGui backend 재생성 시 GPUidle 후 모든 preview binding을 해제하고 새backend에 현재 이미지를 다시 등록한다. GenerationEditor 수명을 ImGui 초기화 뒤로 옮겨 renderer/ImGui 종료 전에worker 및GPU 자원을 정리한다.

- 미리보기는 GenerationEditor의 본창 End 이후별도 Begin/End 창으로 그린다. 처음F8과 함께 열리며 닫기는preview_open만false로 바꾼다. F8 본창의 열기버튼으로복구하고 F8닫기는 두창모두 숨긴다. 따라서 미리보기 조작도 기존F8마우스해제/게임입력차단 범위다.

- 해상도는요청스냅샷에포함하고 변경시이전이미지표시판정에도포함한다. 최대2048² raw float16MiB+RGBA16MiB이며 worker/완료/표시 슬롯과GPU수명은기존최신요청우선구조다. 확대0.25~4배는표시만바꾸고재계산하지않는다. 화면맞춤은1배로되돌리며 이미지viewport의실제창크기기준으로fit을계산해이전확대content크기가다음프레임배율에영향주지않게한다.

## 표면 지층과 연속 점프 변경 (2026-09-13, 미빌드)

- 사용자 실시 승인: 각 X/Z에서 Y=0..511 중 가장 높은 자연 고체를 surface_y로 기록한다(고체 없음은 -1). surface_y는 잔디, 그 아래 1~3칸의 고체는 흙, 나머지 고체는 돌이다. 물/공기 셀은 채우지 않으며 동굴 내부의 별도 바닥이나 아래쪽 공중섬을 추가 표면으로 취급하지 않는다. 이 규칙은 생성 시 적용하며 블록 편집 후 잔디를 자동 전파하거나 지층을 다시 칠하지 않는다.
- 최고 고체 위 셀이 물인 조건은 surface_y+1<sea_level이다. 따라서 surface_y=190이면 수중 표면 흙, surface_y=191이면 윗면이 해수면192에 닿고 위 셀은 공기이므로 잔디다. 세계 높이 끝511도 정상 표면으로 처리한다.
- generate_tile은 groundness 높이 보간 후 find_surfaces를 수행한다. 보수적 height+2*amplitude/squash 상한을 세계 높이로 제한한 위치부터4블록 단위로 내려오며 shape 격자 평면을25점씩 SIMD 계산한다. 직전 평면을 재사용하고, 각 X/Z는 최고 고체를 찾으면 더 탐색하지 않는다. 모든256개를 찾으면 종료하며 임시 메모리는 평면 배열뿐이다. 최악은129개 평면/3225개 노이즈 표본이고 추가 비용은 컬럼 생성 시간에 포함된다. 실제 성능은 미측정이다.
- 판정은 청크 생성과 동일한 셀 중심/삼선형 보간/밀도식을 사용한다. 원본 shape 및 groundness 설정과 JSON 스키마는 바꾸지 않는다. 타일은 불변 컬럼 캐시일 뿐이며 generate_chunk를 단독 호출하면 같은 타일을 직접 계산한다. 다른 청크의 블록·메시를 읽거나 생성 순서에 의존하지 않는다. 경계/AO는 계속 이웃 실제 데이터 준비 후 계산한다.
- 돌 uniform 조기 반환은 보수적 밀도 조건과 함께 최저 surface_y의 흙3층보다 청크 전체가 아래인지 확인한다. 따라서 수직 청크 경계와 월드 상단에서도 표면 재질을 건너뛰지 않는다.
- Space 연속 점프는 기존50ms 이동 루프와 supported()를 사용한다. 공중/천장/물/미로딩 셀은 점프 지지면으로 새로 허용하지 않는다. 짧은 탭 요청과 두 번 누르기 전환은 유지한다. 자동 테스트나 빌드는 추가/실행하지 않았다.

## 옥타브별 groundness 가중치/미리보기 (2026-09-14, 미빌드)

- NoiseSettings.weights는 groundness 전용 vector이며 빈 배열은 내부/레거시 gain 입력을 뜻한다. parse_generation_json과 TerrainGenerator 생성자는 이를 float 곱셈 순서의 [1,gain,gain²,...]로 구체화한다. 미사용 groundness.gain은0.5로 정규화한다. shape의 weights는 허용하지 않는다.
- 읽기는 schema_version1/2/3, 쓰기는3이다. v1은 기존 groundness.gain을 읽고 v2/3은 groundness.weights를 필수로 읽는다. v3은 아래 shape_enabled도 저장한다. weights는 옥타브 수와 같은1..8개, 유한한0이상 float여야 한다. 새 파일은 groundness에 gain을 기록하지 않으며 shape.gain/노이즈 시드/곡선/나머지 설정은 유지한다. 배포 기본 JSON과 사용자 저장 JSON은 이번 작업에서 수정하지 않았다. 게임 내 저장 시에만 새 형식으로 바뀐다. 기존 형식과 수학적 가중치는 같고 정규화 계산 순서에 따른 허용된 작은 float 차이는 가능하다.
- PeriodicPerlin Configure에서 double 가중치 합으로 안전하게 정규화한 float 계수8개를 준비한다. SIMD 2D 누적 루프는0인 옥타브의 노이즈 계산을 건너뛰되 좌표/주기/시드 인덱스는 정상 진행한다. 3D shape 루프는 기존 gain과 정규화를 유지한다. 모든0은2D합0이며 곡선에서 base_height(0)로 매핑된다.
- 공유 noise_controls의 individual 모드를 F8 groundness와 독립 미리보기 양쪽에 적용한다. 드래그/직접 입력, 옥타브별 격자 간격/한글 설명을 제공한다. 옥타브 추가 시 새 가중치는0, 감소 시 제거된 가중치는 버린다. 가로 격자 지수 감소에 따른 옥타브 제한도 가중치 배열 크기에 반영한다. shape UI는 단일 gain이다.
- 미리보기 Request는 octave=-1(합성)/0..N-1과 weighted를 스냅샷한다. 개별 신호는 기본 spacing_log2를 i만큼 줄이고 seed_offset을32비트 모듈러 덧셈으로 i만큼 늘린1옥타브 SIMD 그래프로 샘플링한다. weighted일 때 해당 원신호에 w[i]/sum(w)를 곱하며0기여분은 노이즈 호출 없이0으로 채운다. 이 값들을 더하면 최종 합성이다. 원신호는 가중치0인 옥타브도 볼 수 있다.
- 표시 대상/가중치 적용 전환은 유효 범위에서 비동기 새 요청을 제출하며 최신 요청 우선/취소/GPU 교체 경로를 재사용한다. 일반 파라미터 변경은 기존 생성 버튼으로 갱신한다. 표시된 이미지의 대상/원신호·기여분과 이전 결과 여부를 명시한다. 새 선택도 현재 초안 전체를 사용하며 실제 월드/저장에는 기존 재생성/저장 버튼만 영향을 준다.

## 3D 노이즈 사용 전환 (2026-09-14, 미빌드)

- GenerationConfig.shape_enabled 기본true. JSON schema3에 필수 boolean으로 저장하고 v1/2를 읽을 때는true로 둔다. 저장은3, 읽기는1..3이다. 기존 배포/사용자 JSON을 파일 작업으로 변환하지 않았다. 설정의 equality와 fingerprint에 켜짐 여부도 포함된다.
- F8에 헤더 밖 체크박스를 두어3D 설정이 접혀도 전환할 수 있다. 꺼지면 shape/진폭/세로 격자/압축 편집 영역은 비활성화하되 값은 보존한다. 재생성/저장/되돌리기는 기존 초안 흐름을 따른다. 꺼져 있어도 저장된 파라미터 검증은 유지하여 다시 켤 수 있는 유효 설정을 요구한다.
- TerrainGenerator::shape_active는 shape_enabled && amplitude>0이다. 비활성일 때 shape 노드를 생성/구성하지 않고 vertical_extent_bound는0이다. shape API가 직접 호출되더라도 출력0을 채우며 SIMD3D 호출을 하지 않는다. 기존 진폭0도 같은 계산 생략 경로를 사용한다.
- find_surfaces는3D 비활성 시 보간된 groundness 높이 H로 surface_y=clamp(ceil(H-0.5)-1,-1,511)를 직접 구한다. 셀 중심 y+0.5가 정확히 H면 밀도0이므로 비고체라는 기존 규칙을 보존한다. 이 경로에는3D 평면 탐색이 없다.
- generate_chunk는 기존 uniform 조기 반환 후 높이 이하를 고체/그 위를 y<192 물 또는 공기로 채운다. 3D 격자 좌표 작성/노이즈/삼선형 보간을 모두 건너뛴다. 잔디/아래3칸 흙/수중 표면 흙, 청크 독립성/이웃 AO는 유지한다. 최초 스폰의 보수적 상한도0변형폭을 사용하며 재생성 위치/각도 보존 규칙은 유지한다.
- groundness 원신호 및 옥타브 미리보기는 본래3D를 합성하지 않으므로 켜짐 여부에 따른 이미지 변경/자동 재요청은 하지 않는다. 미리보기와 월드 반영은 계속 별개다.

## 수중 모래3층/흙2층 (2026-09-14, 미빌드)

- 후속 실시로 기존 수중 표면 흙 규칙을 대체한다. 최고 자연 고체의 surface_y>=0 && surface_y+1<192인 X/Z를 수중으로 판정한다. 깊이 surface_y-y가0/1/2이면 모래,3/4이면 흙,5이상이면 돌이다. 육지의0잔디/1..3흙/4이상돌은 유지한다. surface_y190은수중,191은수면에윗면이닿는육지다. 생성된 고체에만 재질을 적용하며 동굴/빈 공간을 채우지 않는다.
- Block enum 끝에 sand를 추가하여 기존 ID를 보존한다. is_solid에 명시적으로 추가해 노출 면/AO/충돌/접지/카메라/레이캐스트가 모래를 고체로 처리한다. WorldEdits::set도 air 또는 등록된 고체를 받도록 변경한다. 현재 선택 슬롯은 기존 흙/잔디/돌3개이며 모래 자동 낙하나 다른 블록은 추가하지 않는다.
- 동일 ground_material 함수가3D 활성/groundness 전용 양쪽 경로에 적용된다. uniform 돌 조기 반환 기준은 각 X/Z 최하단 표면층(surface_y - 수중4/육지3)의 최솟값으로 바꿔 세로 청크 경계에서 추가 흙층을 생략하지 않게 한다. 기존 청크 독립 생성/표면 캐시/이웃 데이터 후 메싱을 유지한다.
- 압축 면의3비트 재질6을모래에사용한다. 아틀라스7타일/224×32와shader실제크기조회에연결한다. 물재질5/투명도, 기존면비트배치는유지한다. 실제생성/렌더링은미빌드다.

## 햇빛/블록광과 하루 주기 (2026-09-14, 도입 이력)

아래 초기48×512×48 일괄 조명/단일 worker 경로는 2026-09-20의 컬럼 내부+경계 전파 절로 대체했다. 조명 값/감쇠/하루 규칙은 유지한다.

- 초기 조명의 LightWorker(별도 jthread)는 현재 컬럼+XZ 이웃8개의 완성된 Column snapshot을 받는다. WorldStream::lighting_columns는 실제 생성된32청크가9컬럼 모두 준비될 때만 반환하며 미준비 상태로 worker를 막지 않는다. 같은 한 겹 데이터 링을 재사용한다. 청크 지형 생성은 계속 독립이며 메싱도 기존 실제27청크 데이터를 사용한다.
- 조명 작업은48×512×48 영역의 실제 블록을 읽는다. WorldEdits::subset으로9컬럼 편집만 복사하고 worker에서 수정 청크당 한 번 copy-on-write해 적용한다. 매 셀 노이즈 재호출/편집 해시 탐색은 없다. 위부터 스캔해 하늘15/공기 수직 유지/물 한 칸당1감쇠/고체 차단을 계산한다. glow 셀은 블록광15의 출발점이다. 두 채널 각각6이웃 전파 큐로 고체를 제외한 셀에1씩 줄어드는 빛을 전달하며 초기 큐에는 밝기 차이가 나는 전파 전선만 넣는다.
- 한 단계마다1감쇠라 밝기가 남는 간접광/블록광 도달 거리는 최대14칸이다. 각 출력 컬럼 주위16칸 데이터 여유와 전 높이 직사광 스캔으로 바깥 경계 가정 없이 중앙16²+1셀halo 조명을 계산한다. X/Z 순환 경계는 canonical snapshot 키로 처리한다. 월드 위는 햇빛15, 월드 아래는0이다. 직사광이 아닌 간접광은 아래로도1씩 감소한다.
- 저장은 LightChunk의 low nibble햇빛/high nibble블록광이다. 핵심16³블록은4096바이트이며 면 꼭짓점 샘플을 위한1겹halo 포함 혼합 청크는18³=5832바이트다. 같은 값 청크는 uniform 하나로 압축한다. 작업 임시 배열은 블록/햇빛/블록광 각각약1.125MiB와 전파 큐이며 결과는32개의 halo청크다. 데이터는 조명 sidecar이며 지형 Chunk를 변경하지 않는다.
- 첫 컬럼은 조명 결과가 준비된 뒤32개청크를 기존 업로드 예산으로 공개한다. 조명 job은 한 번에1개씩 실행한다. 이후 승인된 편집 증분 갱신/큐 순서/결과 일관성은 아래 절을 따른다. 초기 생성과 밝기 미준비 경계의 full solve는 유지한다. 기하 리메싱은 최대8개청크 규칙을 유지하며 조명만 변한 청크의 기하는 재생성하지 않는다.
- regeneration은 기존 조명worker를 stop/join하고 캐시/편집 대기열/완료 결과를 비워 이전 월드 결과가 들어오지 않게 한다. worker 중단은 스캔/전파/출력 패킹 중 주기적으로 확인한다. 종료 시점의 worker snapshot은 불변 데이터를 공유하며 Vulkan 자원을 소유하지 않는다.
- 면별 밝기 uint32는 네 꼭짓점의 두4비트 채널을8비트씩 담는다. 면 외부와 모서리 이웃 중 비고체인 유효 샘플의 채널 평균을 사용한다. 두 측면이 고체이면 대각선을 배제한다. 이 판정은 별도 고체 마스크를 사용하며 AO 비트를 읽지 않는다(후속 수정 상세는 아래 절). 기존 AO와 방향 음영을 곱하고 max(햇빛×낮강도,블록광)을 표시한다. 표시 응답은0.035+0.965*빛²로 어둠의 최소 가독성을 둔다. 0.035 및 새벽05~07/해질녘17~19 보간은 구현 조정값이며 사용자 확정 수치가 아니다.

## 블록 편집 반응과 증분 조명 (2026-09-14, 미빌드)

## 로딩 중 프레임 비용 개선 (2026-09-14, 미빌드)

이 절은 앞선 동기 면 밝기 계산/전체 로딩 범위 재정렬/초기9컬럼 전체 solve 설명을 대체한다. 지형 규칙, GPU 면당8바이트,32청크 컬럼 동시 공개, 개별 편집 청크 갱신은 유지한다.

- MeshLightWorker는 lighting.*에 추가된 별도 jthread다. 초기/편집 ChunkMesh를 이동받아 고체면→물면 순서로 합치고 모든 면의 꼭짓점 밝기를 계산한다. 빛 전용 작업은 기존 geometry/이전 밝기 배열을 공유받아 새 값을 계산·비교한다. Vulkan은 호출하지 않는다. worker 루프는1024면마다 stop을 확인한다. 기하 편집 요청은 일반 조명/초기 작업보다 앞에서 FIFO로 처리하며 같은 키의 아직 시작하지 않은 작업은 새 요청으로 대체한다.
- WorldView의 packing_은 canonical ChunkKey→단조 증가 ticket이다. 같은 청크를 편집하거나 언로드하면 ticket을 무효화하고, 완료 결과가 현재 ticket과 다르면 버린다. 재생성은 worker를 stop/join하고 완료 큐/대기 키를 비운다. LightChunk와 CPU geometry는 공유 불변 snapshot이므로 worker가 main의 변경 가능한 블록/렌더 상태를 읽지 않는다. 완료 큐는 mutex 아래 swap하고 면 계산/배열 비교는 잠금 밖에서 수행한다.
- prepare는 직접 편집 기하를 먼저 만들어 긴급 CPU 패킹을 예약한다. 그 다음 준비된 결과를 GPU에 업로드하며 보이는 컬럼의 기하 결과를 먼저 받는다. actual 업로드는 최대4청크/2MiB/2ms soft budget이다. 진척을 위해 첫 유효 완료 청크 하나는 시간 예산이 지나도 마무리한다. 편집 기하 CPU 생성도 최대4청크/2ms soft budget이므로 request나 개별 메싱/할당까지 합친 프레임 전체의 엄격한2ms 상한은 아니다.
- 초기 패킹과 빛 전용 패킹은 각각 프레임당 최대4개, 전체 현재 대기 키32개 미만일 때 예약한다. 편집은 이 일반 대기 상한보다 우선한다. 면이 없는 초기 청크는 패킹/버퍼 생성 없이 완료 처리한다. 컬럼은32개 완료 bit와 해당 컬럼의 미처리 빛 패킹/업로드, 진행 중 광전파/대기 편집이 모두 끝나야 공개한다. 기하가 계산 당시보다 새 조명 snapshot을 만나면 기하를 우선 반영하고 최신 빛 전용 작업을 다시 예약한다.
- Renderer::upload_buffer는 Frame별 지속 매핑 staging page(최소2MiB)에서 범위를 나누어 쓴다. 프레임 fence 완료 후 page.used만0으로 돌리고, 같은 페이지를 사용한 모든 GPU 복사가 끝나기 전에는 재사용하지 않는다. 오프셋은 max(4, nonCoherentAtomSize)에 정렬하고 실제 범위를 flush한다. VkBufferCopy.srcOffset을 해당 범위로 지정한다. 페이지는 부족할 때 추가하고 최고 사용량만큼 유지하며 renderer 종료/device idle 후 해제한다. 최초 페이지 생성 비용과 실제 GPU 목적지 버퍼 할당은 남는다. 텍스처용 staged 경로는 기존 별도 업로드 경로다.
- FacePool은1024개 set의 사용 가능한 수를 가진 공유 상태다. available==0인 풀에는 Vulkan 할당을 호출하지 않는다. 정상 할당 때 감소하고 fence 뒤 실제 descriptor free 때 증가한다. 예상치 못한 pool 메모리/fragmentation 실패도 여유0으로 표시하여 같은 실패를 매 업로드마다 반복하지 않는다. deferred callback은 WorldView를 캡처하지 않고 풀의 공유 상태를 소유하며, 모든 set 해제 이후 pool이 파괴된다.
- F3 GPU 메모리는 vmaCalculateStatistics 대신 vmaGetHeapBudgets의 statistics.allocationBytes/blockBytes를 합산한다. 기존의 사용/예약 의미를 유지하고 전체 하위 할당/빈 공간 순회는 제거한다. WorldView::mesh_bytes도 공개/편집 교체/언로드/재생성 때 누적값을 갱신한다. pending()은 원자적 카운터라 F3가 scheduler mutex를 기다리지 않는다. CPU 월드 준비 시간은 stream request/언로드부터 측정하며 기존 표시명 CPU 업로드 기록을 CPU 월드 준비로 바꿨다.
- WorldStream::request는 새 원형 범위와 이전 원형 범위의 Z행별 X구간을 빼서 들어오고 나가는 컬럼만 얻는다. 한 칸 이동에서 전체 원의 좌표를 다시 열거하지 않는다. 이동·반경 변경·큰 이동·8192컬럼 순환을 처리하며 멀리 떨어진 두 범위 사이의 빈 Z행도 건너뛴다. 각 가시 컬럼이 요구하는3×3 데이터 컬럼에 참조 수를 유지하고0↔양수 전환만 생성/해제한다. 기존 작업 큐 전체 stable_sort/가시 priority_ 전체 재구축은 제거하며 추가된 컬럼만 거리순 정렬한다. 초기 진입/큰 반경 증가에 필요한 전체 새 상태 생성 비용은 남는다.
- 새 상태 객체 생성과 제거 객체의 큰 배열 해제는 scheduler 잠금 밖에서 한다. 맵/큐 상태 변경은 잠금 안에서 하고 실제 이웃 메싱 예약은 worker의 reschedule_에서 수행한다. take_ready는 pump를 main에서 실행하지 않는다. 이미 active8 한도 때문에 기다리는 컬럼은 데이터 완료마다 같은27이웃을 다시 검사하지 않는다. 기존 큐의 취소 항목은 소비할 때 건너뛰며 새로운 작업의 정렬은 새 항목에만 적용한다.
- 2026-09-20 사용자 실시 승인으로 대기 컬럼의 활성화 경합을 수정했다. waiting 컬럼은 빈 active 슬롯이 생겨도 데이터 완료 경로에서 활성화하지 않는다. pump_locked가 후보 큐에서 꺼내 waiting을 해제하고 동일 mutex 안에서 세로32청크를 모두 재검토한다. 이미 준비된 청크의 예약이 누락되어 컬럼 완료가 영구 대기하는 경로를 차단하며, 아직 준비되지 않은 이웃은 기존 데이터 완료 알림으로 예약한다. active8 제한과 컬럼 동시 공개는 유지한다.
- main의 take_ready/halo/lighting_columns는 try_lock으로 잠금 경합 시 다음 프레임으로 미룬다. pending 카운터와 별개로 worker 실패는 이 조회 경로에서 계속 전달한다. WorldView 언로드도 request가 반환한 leaving 목록만 조회하여 매 이동마다 공개 컬럼 전체를 다시 검사하지 않는다. 생성 worker는 기존 최대4개이며 광전파1개+면 패킹1개가 추가로 실행된다.
- 초기 조명은 같은 편집 기준 상태의 이미 준비된 이웃 ColumnLight를 known[9]로 받는다. known 컬럼의 블록/COW 편집/직사광 전 높이 스캔과 내부 전파는 생략한다. 새 컬럼과 미준비 이웃만 초기화하고, known에 접한 면의 정확한 기존 밝기를1감쇠시켜 새 영역으로 주입한다. known 값을 바꾸거나 미준비 경계를 하늘로 가정하지 않는다. 초기 scratch 배열의48×512×48 할당/출력 halo 패킹은 남지만 재사용된 컬럼 내부의 중복 계산은 줄어든다.
- 최초 재사용 가능한 이웃이 없을 때는 기존 전체 영역 계산과 같으며, 편집 경계 fallback은 이전 밝기가 변경 전일 수 있어 known 재사용 없이 현재 데이터로 재계산한다. 초기 job을 미처리 편집보다 앞세우지 않는 기존 순서로 cached 조명 기준 상태를 맞춘다. 초기 외곽 부분 계산을 완성된 컬럼으로 오인해 캐시하지 않고 정확한 중앙 출력만 캐시한다.
- 이 변경은 source/정적 검토 단계다. 자동 테스트·빌드·실행은 하지 않았다. 실제 FPS/로딩 시간 개선량, thread 수 증가의 CPU 경합, staging 최고 사용량, 경계 정확성은 다음 승인된 빌드 후 수동 확인이 필요하다.


## 컬럼 생성·내부 조명·경계 전파 파이프라인 (2026-09-20, 미빌드)

- WorldStream의 `column` 작업은 TerrainTile을 한 번 계산하고32청크 데이터를 생성한다. 결과 배열을 잠금 아래 한 번에 게시한 뒤 `local_light`를 예약한다. 청크 계산 함수는 시드/좌표만으로 재현 가능하며 이웃 블록에 의존하지 않는다. 작업 단위를 컬럼으로 바꾼 것이고 지형 함수나 생성 결과를 변경하려는 작업이 아니다.
- `local_column_light`는16×512×16 내부에서 직사광을 위부터 계산하고, 내부 햇빛/발광원에서 각 채널 플러드 필을 완료한다. 스레드별 블록/두 채널/큐 scratch를 재사용한다. 결과는 DataColumn의 불변 local_light이며 같은 데이터가 유지되는 동안 한 번만 계산한다. 내부 계산은 다른 컬럼을 기다리지 않는다.
- 경계 확정 작업은 대상 컬럼과 X/Z8이웃의 내부 결과가 준비되면 예약한다. 3×3은 기존 내부 조명 snapshot을 읽는 범위이며,9컬럼 직사광/내부를 다시 계산하는 영역이 아니다. 모든 공유 X/Z 면을 한 번씩 비교해 반대편 밝기를 실제로 증가시킬 수 있는 셀만 전파 큐에 넣는다. 이후6방향 전파가 내부와 다음 이웃 경계를 계속 넘으며, 변경된 청크만 copy-on-write한다.
- 경계 작업마다 대상 컬럼의 확정 결과만 반환한다. 이웃의 내부 캐시는 변경하지 않고 각각의 대상 작업에서 재사용한다. 같은 경계면 비교가 인접 대상 작업에서 중복될 수 있으나, 전역 가변 조명 맵이나 작업 간 쓰기 잠금 없이 여러 컬럼을 병렬 처리한다. 각 경계 작업은 실제 한 겹 이웃 전체를 확보한 후 시작하며, 미준비 이웃을 공기/햇빛으로 추정하지 않는다.
- 직사광은 각 컬럼 전 높이에서 이미 확정되며, 간접광/블록광15가1씩 감쇠해 양의 값으로 도달하는 거리는14칸이다. 따라서16블록 한 겹이면 대상16² 및1셀 샘플 halo까지 정확히 확정할 수 있다. 경계 밖 결과를 기다리는 무한 연쇄 대기가 없다. 순환 키는 canonical을 사용한다.
- 내부 결과의 X/Z halo는 균일 압축을 위한 가장자리 복제값이며 공개/면 밝기에 직접 쓰지 않는다. 경계 연결의 finish(target)는 대상32개 청크의 halo와 고체 마스크를 실제 이웃으로 전부 확인한다. 값이 같아 기존 포인터를 재사용하는 경우도 실제 샘플 전체를 비교한 결과다.
- 경계 작업 완료 후32개 메시를 한 번에 예약하며, 모든 메시 완료 시 BuiltColumn이 완성 조명과 함께 전달된다. active8 한도는 경계 조명부터 완료 큐 소비까지 적용한다. waiting은 pump만 해제하므로 앞선 일부 청크 예약 누락 경로도 유지되지 않는다. 여러 worker가 서로 다른 컬럼의 데이터/조명/메시 단계를 처리하고, main은 그동안 이전 컬럼을 업로드한다.
- WorldView는 주변3×3에 세션 편집이 없으면 전달된 확정 초기 조명을 즉시 사용한다. `has_nearby`는 AO에 영향을 주는 인접 셀만이 아닌 주변 컬럼의 모든 편집을 확인하므로, 이웃 내부의 발광/차광 편집도 누락하지 않는다. 편집이 있으면 기존 직렬 LightWorker 경로로 현재 편집을 반영한 내부 조명과 경계 연결을 수행한다. 이 대체 경로도 큰48³계열 scratch solve 대신 같은 local/connect 함수를 쓰며, 현재 편집 기준으로 확정된 이웃 결과는 재사용한다.
- 편집의 제거/추가 증분 플러드 필, 연속 편집 기준 상태, 청크별 기하 갱신, 업로드 예산과 컬럼32청크 동시 공개는 유지한다. 데이터 전용 외곽 링에도 내부 조명을 보관하므로 RAM 사용량은 이전보다 늘 수 있다. 편집이 많은 재로딩 지역의 조명 대체 경로는 아직 직렬이다.
- F3의 최근 컬럼 항목에 초기 조명 시간을 추가한다. 실제 요청→공개 시간이나 전체 로딩 시간은 아니며, 성능 향상/그림자 경계/메모리 최고 사용량은 빌드 후 실행 확인이 필요하다.
