# 일반 지형 push constants 분리 비교 — 미채택 (2026-10-01)

카메라 행렬을 청크마다 전달하는 중복을 줄이는 후보를 구현하고 비교했다. 거리별·반복별 CPU 결과가 엇갈려 채택하지 않았으며 제품 코드는 비교 전 상태로 복원했다. 앞서 채택한 블룸16샘플은 유지한다.

## 후보 구현

world_view.cpp의 일반 지형 패스에서64바이트 카메라 행렬을 매 프레임 한 번 전달하고, 청크마다 offset/sun과 선택 표시32바이트만 offset64부터 전달했다. 행렬은 이동·회전 중에도 매 프레임 갱신하며 정지 여부에 따른 생략은 없다. 셰이더의96바이트 레이아웃과 target offset80, draw/descriptor 호출·순서·지형·선택 판정은 유지했다. LOD/물/얼음/플레이어/그림자 경로는 변경하지 않았다.

그리기 N회일 때 API에 제공하는 payload는96N에서64+32N바이트로 줄지만, push 호출은 N에서 N+1회로 늘어난다. 거리32의1,819회에서는174,624→58,272바이트다. 이는 API 인자 크기의 합이며 실제 PCIe 전송량이나 GPU 메모리 트래픽 측정값이 아니다. 후보의 near_pushes는 near_draws+1이며 복원 후에는 다시 near_draws와 같다.

## 성능 결과

각 변형1920steady프레임 평균과 nearest-rank p95, 단위ms다.

| 거리 | 일반 CPU 전→후 | 변화 | 일반 p95 전→후 | 준비+일반+LOD CPU 전→후 | 전체 GPU 전→후 |
|---|---|---|---|---|---|
|12|0.033420 → 0.032179|3.7% 감소|0.048900 → 0.047100|0.096734 → 0.095866|1.656800 → 1.657758|
|24|0.136101 → 0.126360|7.2% 감소|0.207700 → 0.188600|0.204424 → 0.191098|1.371314 → 1.367440|
|32|0.251381 → 0.263002|4.6% 증가|0.385500 → 0.426400|0.328023 → 0.344204|1.480166 → 1.505555|

거리12는 첫 쌍만 감소했고 나머지는0.031242→0.031338, 0.034552→0.035037로 증가했다. 거리24는 앞선 두 쌍 감소/셋째 증가, 거리32는 앞선 두 쌍 증가/셋째 감소였다. 총9쌍 중4쌍만 감소했다. 변경하지 않은 LOD CPU 평균도 거리24에서5.5% 감소하고 거리32에서6.5% 증가했으므로 실행 환경 변동이 포함되어 있다. 이 수치만으로 분리 구현이 본질적으로 느리다고 단정하지 않지만, 채택을 뒷받침할 일관된 이득도 입증하지 못했다.

데이터 크기가 줄어도 호출 횟수·드라이버 처리 비용·명령 버퍼 기록 비용이 같은 비율로 줄지는 않는다. 드라이버 내부 비용은 따로 계측하지 않았으므로 단일 원인을 단정하지 않는다. 전체 GPU/FPS 향상도 주장하지 않는다. 통계는 [JSON](benchmarks/near-push-2026-10-01-summary.json)에 보존한다.

## 출력 검증과 범위

성능18회 모두exit0/Vulkan errors0/warnings0/UI0/texture0, 각640steady CPU/GPU frame 일치, LOD pending/queued0과 API 카운터 관계를 확인했다. 일반 draw209/1017/1819, triangles570112/1035648/1494656, LOD tiles402/447/489는 전후 같다. LOD draw 수는 기존 업로드 part 분할에 따라 소폭 달랐다.

별도 validation8회는 모두exit0/errors0/기존 미사용 셰이더 출력 warnings10/UI0/texture0. 각64steady 출력량이 전후 같으며 표준 시점의 raw 그림자4종과 extent.txt는 바이트 동일하다. 기본 시점 전후 PNG를 직접 확인해 지형·선택 테두리·플레이어 그림자가 같은 구성이었다. 성능 PNG9쌍의 평균 절대 RGB 채널 차이는 최대0.398612/255다. TAA 위상이 일치하지 않아 픽셀 완전 동일성을 주장하지 않는다.

실제 이동·회전 입력, 블록 편집, F4 전환과 창 리사이즈를 구동한 검증은 아니다. 여러 초기 시점과 소스의 매 프레임 갱신 경로를 확인했다. 자동 테스트/CTest/CU/합성 입력은 추가하지 않았다.

## 최종 복원

후보 소스와 patch/after.exe는 위 격리 폴더에 보관했다. world_view.cpp만 비교 전 사본으로 복원하고 수정시간을 갱신한 뒤 Release 빌드·패키징했다. src/world/world_view.cpp는 HEAD와 diff가 없고 비교 전 사본과 해시가 같다. build/near-push-restored-build.log에서 해당 cpp의 실제 재컴파일과 실행 파일 링크를 확인했다. 패키징 로그는 build/near-push-restored-package.log다.

복원 실행은 validation/세부 계측 ON, 거리12/64steady에서exit0/errors0/기존 warnings10/UI0/texture0. CPU/GPU frame 일치, near_draws=near_pushes=209로 기존 방식 복귀를 확인했다. LOD tiles402/triangles570112, raw 그림자4종+extent가 before와 같았다. TAA ON 복원 PNG는 평균 절대 채널 차이0.036188/255, 최대5이며 완전 동일은 아니다.

build/bin·out/DOLBUTO·restored.exe의 SHA256은 모두181E0DC4EFF48D5B15FE992A103E4F0AC18F3A61F0DB2C1E9EF6EE0C81EC43EB다. 재빌드 EXE는 before와 바이트 동일하지 않으므로 소스 일치·실제 재컴파일·실행 카운터로 복원을 확인했다. 모든 SPIR-V는 비교 전/빌드/배포가 같고 블룸16샘플을 유지한다. 패키지 settings.json SHA256 67E209936EE549CD91945CF19FF059751F71C5DE5BFD3FBB188A75BB7168419B 보존. 이번 작업은 비교 기록만 남기며 commit/push는 수행하지 않았다.
