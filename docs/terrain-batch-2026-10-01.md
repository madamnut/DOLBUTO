# 일반 고체 지형 명령 묶기 비교 (2026-10-01)

사용자 거리32 CPU 병목 개선 제안 후 `ㄱㄱ` 승인으로 목록 준비·정렬·명령 기록 계측, 일반 고체 지형의 다중 간접 그리기 구현, 전후 헤드리스 비교를 수행했다. 기존 카메라 XZ 거리순·AO·밝기·그림자·구름은 유지한다.

거리32 CPU 병목 개선을 목적으로 채택했다. 전체7쌍 중6쌍에서 CPU 작업과 프레임 간격이 줄었고,6000steady 추가4쌍은 모두 개선됐다. 전체 표본 합산 CPU 작업10.97%·프레임 간격10.61% 감소, 대신 GPU 평균은0.009605ms(0.65%) 증가했다. GPU 자체의 최적화로 주장하지 않는다. 초기3쌍의 전체 p95 악화와 마지막 추가 쌍의 큰 편차도 포함했다. 추가4쌍의 CPU 평균 감소폭은 약7.1/8.7/9.2/23.0%로 변동하므로11%를 모든 장면의 고정 개선율로 일반화하지 않는다. GPU 제한인 다른 거리에서의 성능 향상은 확인하지 않았다.

## 구현

매 청크의 push constants/descriptor/draw를 반복하던 일반 고체 지형 경로를 거리순 청크 목록+간접 명령 배열로 바꾼다. 버퍼 장치 주소로 기존 면/밝기 버퍼를 참조해 기하를 다시 만들지 않는다. LOD가 사이에 있으면 연속 근거리 구간까지만 묶고 다음 구간에서 pipeline/atlas/environment를 재설정한다. maxDrawIndirectCount를 넘는 구간은 나누고 first_draw+gl_DrawID로 올바른 청크를 선택한다. face index는 기존 gl_InstanceIndex이며 모든 간접 명령의 firstInstance는0이다.

장치가 multiDrawIndirect/shaderDrawParameters/bufferDeviceAddress를 모두 지원할 때만 기능을 활성화한다. 프레임 슬롯별 청크48바이트/간접 명령16바이트 버퍼는 슬롯 fence 완료 뒤 갱신·확장하고 제출 전에 flush한다. 현재1819청크는 슬롯별2048개 용량으로 두 슬롯 합계256KiB다. 메시·조명 교체의 기존 deferred lifetime과 upload barrier를 유지한다. world.vert의 TERRAIN_BATCH 변형만 추가 생성하며 원래24개 SPIR-V는 전부 동일하다. 물/얼음/그림자/LOD draw 자체와 디버그 경로는 기존 코드다. 미지원 장치는 자동 직접 그리기, --profile-direct-terrain은 진단용 직접 그리기다.

[Vulkan 다중 간접 그리기](https://docs.vulkan.org/refpages/latest/refpages/source/vkCmdDrawIndirect.html)와 [버퍼 장치 주소](https://docs.vulkan.org/samples/latest/samples/extensions/buffer_device_address/README.html)의 API 규약을 따른다.

## 측정 조건과 반복성

i7-14700F/RTX5060, Release,1280×900 헤드리스2슬롯, 근거리32/LOD64, 평지 seed1337, 카메라(8,193.6,8)/yaw−90/pitch−22/정오12, TAA ON/블룸12, 그림자 품질2·거리192. 다른 설정은 실행별 보존 JSON 참조. 근거리·조명·업로드·LOD 완료 뒤240프레임 예열. 성능 실행은 GPU/frame 계측만 켜고 draw/validation/capture는 끈다. 모든 steady 프레임을 사용하고 이상치는 제거하지 않는다.

최초1200steady×전후3쌍은2쌍 개선/1쌍 악화로 반복성이 부족했다. 이를 삭제하지 않고6000steady×전후4쌍을 추가했다. 초기 순서는 before/after →after/before →before/after, 추가 순서는 after/before →before/after →after/before →before/after다. 추가 측정은 완성 소스·바이너리를 바꾸지 않고 표본 길이만 늘렸다. CPU/GPU frame ID와 steady 출력량을 대조했다. CPU 시간은 메인 스레드의 명시적 대기를 뺀 경과 시간이며 worker 전체 사용률이 아니다. 프레임 간격은 기록 저장 비용도 포함한다. CPU와 GPU는 병렬로 실행되므로 두 시간을 더하지 않는다.

## 검증·한계

- 지상 거리32, 순환 경계/상공/LOD OFF 거리12 전후8회 +거리32 강제 직접 경로1회: 각각64steady, TAA OFF/블룸40/validation ON/거리순 진단. 모두 종료0/Vulkan 오류0/기존 미사용 셰이더 출력 경고10. PNG 픽셀 동일, raw 그림자4종+extent 파일 동일. 선택 블록 표시 포함 지상 캡처를 직접 확인했다.
- 성능14회55,200steady 및 세부2회2400steady 모두 종료0/오류0, LOD pending/queued0, CPU/GPU frame ID 및 전후 출력량 일치. 성능의 경고0은 검증 레이어를 껐기 때문이며 별도 validation과 구별한다.
- 새 SPIR-V의 capability/오프셋/stride/정렬 확인과 spirv-val 성공. C++ 레이아웃 static_assert, 슬롯 fence 후 갱신, 조명만 교체하는 경로·퇴거·재생성 수명은 소스 검토했다. 실제 미지원 GPU·입력 이동/블록 편집/리사이즈/재생성/유체 장면은 실행하지 않았다. 현재 시점들의 steady는 근거리 묶음1개이므로 LOD 사이 다중 구간 및 장치 최대 개수 분할을 강제로 만들지는 않았다.
- 첫 거리32 seam validation은 지상32 전후 성공 뒤 추가 시점 검증을12로 조정하면서0.94초에 중단(exit−1)했다. 제외 원본은 excluded-radius32-seam에 남겼으며 해당 시점을12로 전후 재실행했다. 완료된 성능 표본은 제외하지 않았다.
- 자동 테스트/CTest/CU/합성 입력 없음. 결과는 완전 로딩된 고정 평지이며 실제 창의 입력→표시 지연이나 이동 중 스트리밍 개선으로 일반화하지 않는다.
