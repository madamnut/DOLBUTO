# 노이즈 성능 측정 기록 · 2026-09-24

AI 작업 컨텍스트와 재현 기록. 사용자 승인에 따른 별도 성능 측정이며 자동 회귀 테스트는 아니다. 게임 생성 규칙/구현/사용자 JSON은 변경하지 않았다.

## 환경과 조건

- CPU: Intel Core i5-13400, 10코어/16스레드. Windows 11 Pro 10.0.26200. 균형 조정 전원 계획을 유지했다. GPU는 이 측정에 사용하지 않는다.
- 측정 스레드: 논리 CPU0에 고정, Windows EfficiencyClass1, CPUID core type64(0x40, P-core). 단일 스레드, AVX2 실제 선택을 세 노드 모두 확인했다. 프로세스 우선순위나 전원 정책은 바꾸지 않았다.
- LLVM clang-cl23.1.0, C++20, CMake Release. FastNoise2 v1.1.1(903c1f2d2f9d53ddce94cd223f32727d9ab3aeaa), FastSIMD16450dae9528727e500e7254f635a671f9c7ee2d. 라이브러리 기존 RELAXED SIMD 빌드(/fp:fast)를 그대로 사용한다. 벤치마크 변환 루프는 기본 Release이며 std::sin/cos의 float 오버로드를 사용한다.
- 기준 격자 간격1024, 1/6옥타브, gain0.5, lacunarity2. 6옥타브는 FastNoise FractalFBm과 게임의 내부 fBm을 각각 사용한다. 출력 진폭 합을 정규화한다. 구현 경로가 다르므로 6옥타브 비교를 순수 단일 노이즈 알고리즘 비용으로 해석하지 않는다.
- 출력 샘플 수25(5×5, 간격4블록),256(16×16, 간격1블록),65536(256×256, 간격512블록). 작은 묶음은 호출/꼬리 SIMD 비용을 포함한다. 크기마다 공간 범위도 달라지므로 배치 크기만 바꾼 실험은 아니다. 모든 방법은 같은 개수와 기본 X/Z 좌표를 사용한다.
- 초기 좌표 X251.375/Z531.25, 토러스 주기131072, 반지름131072/(2π). (Rcosθx,Rsinθx,Rcosθz,Rsinθz)를 입력하고 노드 scale1024를 적용한다. 4D 노이즈 자체는 미리 만들어 둔 이 토러스 좌표에서 측정했다. 일반 Perlin은 비주기 기준이며 전체 월드 대체 기능을 제공하는 것은 아니다.
- 모든 방법은 GenPositionArray2D/4D SIMD API, 기존 min/max 계산 포함. 생성기 구성/메모리 할당/최초 XZ 생성/통계·파일 쓰기는 타이밍 밖. 출력 버퍼는 재사용한다. 결과를 관찰 가능한 checksum으로 소비하여 제거를 막고 이 작은 공통 비용은 타이밍에 포함된다. 단일 배치를 반복하므로 warm-cache 마이크로벤치마크다.
- 각 조건마다 사전 워밍업과 반복 횟수 보정 후 약20ms 목표의 반복 호출을 한 관측값으로 기록했다. 관측 라운드마다 방법 순서를 섞고 호출 시드를 바꾼다. 31회×독립 실행2번 = 조건별62관측, 총1860관측. 평균/표본 표준편차/중앙값은 관측별 ns/sample에 대해 계산하며 개별 샘플의 지연 분포는 아니다. 이상값 제거 없음. 최대200만 반복 제한 때문에 아주 빠른 소배치의 일부 관측은20ms보다 짧을 수 있다.
- 첫 실행에 편차가 보여 동일 조건으로 재측정하고 두 실행을 모두 합쳤다. 실행 중 전체 CPU 사용률42%가 한 차례 관측되어 전용 유휴 환경이 아니다. 부스트/백그라운드 작업의 영향이 있을 수 있으므로 중앙값으로 비교하고 표준편차도 보존한다. CPU 사용률은 지속 기록한 평균이 아니다.

## 해석과 한계

65536샘플 기준 일반2D Perlin 대비 4D Simplex(좌표 준비됨)의 중앙값 비율은1옥타브3.915배,6옥타브3.680배다. 현재 주기적2D Perlin 대비는3.567배/3.977배이며 축별 토러스 변환 포함은4.893배/4.203배다. 두 번째 독립 실행의 큰 묶음 중앙값은 첫 번째보다 약4~10% 낮았다. 절대 수치는 환경 영향을 받지만 순위는 유지됐다. 두 실행 모두 포함하고 유리한 실행만 선택하지 않았다.

좌표 준비됨은 sin/cos 및 배열 생성 비용이 없다. 축별 재사용은 규칙적인 X/Z 격자의 각 축에서 sin/cos를 계산하고 4개 좌표 배열을 채우는 비용을 매 호출 포함한다. 점별 sin/cos는 매 샘플에서 네 초월함수를 다시 계산하는 일반 좌표 경로다. 두 변환 경로는 모든 배치/옥타브에서 최종 출력 최대 차이0을 확인했다. 점별 경로의 비용을 4D Simplex 자체의 필수 비용으로 일반화하지 않는다. SIMD sin/cos나 노드 내부 융합은 구현하지 않았으므로 변환 경로의 최적 성능 상한이 아니다.

워핑으로 X/Z가 불규칙해지면 현재 축별 재사용이 그대로 가능한 것은 아니다. 반대로 여러 신호가 같은 변형 좌표를 사용한다면 4D 좌표 생성 비용을 공유할 여지가 있다. 2D/4D 노이즈는 무늬와 통계 특성이 달라 결과 지형이 동일하지 않으며, 이 측정은 시각 품질을 평가하지 않는다. 지형 보간·스플라인·표면룰·조명·메싱·스케줄링을 포함하지 않아 전체 청크 생성 시간이 이 배율로 늘어난다는 의미가 아니다.

## 산출물과 실행

- 원시 관측: benchmarks/noise-2026-09-24-raw.csv
- 전체 통계: benchmarks/noise-2026-09-24-summary.csv
- 소스: tools/benchmarks/noise_benchmark.cpp
- 빌드: Release configure 후 cmake --build --preset release --target noise_benchmark
- 실행: build/release/bin/noise_benchmark.exe 새출력경로.csv
- 로그: build/release/noise-benchmark-build.log, noise-benchmark-run.log, noise-benchmark-repeat.log

EXCLUDE_FROM_ALL로 일반 빌드에 측정 실행이 추가되지 않으며 package.ps1도 측정 실행 파일을 배포하지 않는다. 컴퓨터 유즈/합성 입력은 사용하지 않았다. 기존 자동 테스트를 복구하지 않았다.
