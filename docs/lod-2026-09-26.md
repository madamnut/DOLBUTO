# 세션 LOD — AI 구현 컨텍스트

승인: 사용자 DH식 LOD 제안/디스크가 아닌 세션 내 유지/정지 상태 주변 생성 확인 후 `실시`.

## 구성

- `world/lod.*`: 한 작업 스레드가 데이터/축약 트리/메시 선택을 소유한다. main 및 WorldStream worker는 짧은 잠금으로 요청/컬럼 스냅샷/셀 변경만 전달한다. 렌더 스레드에서 생성/축약/메싱을 하지 않는다.
- `WorldStream::data_ready_`: 일반 컬럼 블록 생성 직후 immutable Chunk 배열을 공유해서 전달한다. 입력 큐 최대32컬럼. 초과 시 기본 생성기의 추후 LOD 작업으로 보충한다. 이웃조명/메시는 기다리지 않는다.
- 먼 컬럼: 동일 TerrainGenerator/generate_tile/generate_chunk 32개를 사용. 원본 컬럼을 일시적으로 만들고 LodData 추출 후 폐기한다. 조명 전파/AO/일반 메시/유체 물리는 수행하지 않는다. 20TPS나 실제 로딩 반경은 바꾸지 않는다.
- LOD 생성은 가장 가까운 컬럼부터 한 개씩, 일반 청크 pending/조명/편집/packing/incoming이 있으면 새 원거리 생성을 보류한다. 진행 중에는 청크 사이에서 요청 변경/취소를 확인한다. 가까운 블록 생성 결과의 LOD 추출은 계속 가능하다.
- 범위가 다 채워지면 조건변수로 대기한다. 이동/거리 변경으로 요청 목록을 재작성한다. 캐시가 적정 단계로 이미 덮는 컬럼은 생성 생략.

## 데이터와 축약

LodKey x/z는 원점의 컬럼 좌표, level마다 정렬 간격 2^level. 한 노드에 16x16 기둥, 기둥의 가로폭은 1/2/4/8/...블록, level0노드가 실제컬럼16x16이다. level9까지 지원하며 월드131072와 모든 정렬이 맞는다.

각 기둥은 하단부터 `(bottom, top, material)` 구간 배열. Y는 1/256블록으로 저장하여 눈1/16·노출수면7/8·유체표시단계를 보존한다. 빈 공간은 구간 사이의 틈이다. 단일 높이맵이 아니므로 동굴/돌출면을 저장할 수 있다. 물 모서리의 반 단계 보간은 LOD에서 평면으로 근사한다.

네 자식이 모이면 각2x2기둥의 모든 높이 경계를 합쳐 구간별 재질 다수결로 축약한다. 3개 이상 빈칸이면 빈 공간, 2개 빈칸 동률은 고체/유체를 남긴다. 나머지는 재질표 순서로 동률을 해소한다. 얇은 구조물/작은 구멍은 높은LOD단계에서 없어질 수 있다. 부모 데이터가 이미 있고 형제의 세부 데이터가 퇴거됐으면 변경된 자식에 해당하는8x8 사분면만 다시 축약한다.

근거리 반경+3컬럼과 맞닿은 노드는 가능한 level0까지 내린다. 그 외에는 타일과 플레이어 사이 최단 거리/step 기준, step*4컬럼보다 가까우면 세밀한 단계 요청. Z/FOV는 이 판단과 생성 요청에 전달하지 않는다. 아직 필요한 세부 데이터가 없으면 캐시의 거친 부모를 사용한다. 한 번의 선택에서는 부모/자식이 중복되지 않는다. 세밀한 데이터가 덜 준비되거나 예산상 퇴거됐을 때 일시적으로 거친 경계를 볼 수 있다.

## 메시/렌더/경계

- `render/lod_renderer.*`, `lod.vert/lod.frag/lod_shadow.frag/lod_mask.glsl`.
- 면당16bytes의 procedural 인스턴스 vertex 입력. Y구간/셀/축/재질/간략 하늘빛을 담는다. 타일 내부 가려진 면은 구간 교차로 제거한다. 바깥쪽 수직 면을 닫아 서로 다른 단계의 높이 차를 연결한다. 경계를 부드럽게 morph하는 방식은 아니므로 단순화된 계단은 보일 수 있다.
- 매 프레임 슬롯별129x129 실제 공개 컬럼 마스크. 실제청크 업로드/공개가 끝난 곳만 fragment discard한다. 하나의 큰 LOD 타일 전체를 숨기는 방식이 아니다. 로딩 범위는 기존 원형, LOD 바깥 테두리도 원형으로 자른다. 정밀 청크가 빠지면 마스크가 풀려 남아 있는 LOD를 사용한다.
- CPU double 카메라 상대 좌표/순환거리 사용. 마스크는 타일 원점+local좌표로 계산해서 월드 끝의float정밀도에 의한 컬럼 오분류를 피한다.
- 새 선택 묶음의 GPU 업로드가 모두 끝난 뒤 묶음 전체를 교체하여 계층 교체 중 중복/빈틈을 피한다. 매프레임 업로드1MiB,CPU기록 약1ms 상한; 큰 타일도 여러 buffer part로 나누어 프레임에 분산한다. 재생성/버퍼교체는 renderer.defer로 GPU 사용이 끝난 뒤 해제한다.
- 프러스텀 컬링, F4단계색, 태양/밤/주변광/기존 그림자 수신, LOD 그림자 고체깊이재사용·물추가, 실제 깊이/대기/구름가림/TAA/근거리SSR에 연결한다. 안개범위는 LOD 켜짐시 max(일반거리,LOD거리).
- 재질별 텍스처의 선형RGB 평균을 사용한다. glow/lava 발광 포함. 먼 물은 후속 승인으로 고체와 분리하여 기존 WaterEffects의 snapshot/SSR/노멀/프레넬/하늘·구름 반사 및 수심 합성을 공유한다. 물속 지형은 축약된 LOD이므로 정밀 블록과 완전히 같지 않다. 먼 얼음은 여전히 불투명 간략 재질이다. 근거리 실제청크로 교체되면 원래 재질을 사용한다.
- 원거리 하늘빛은 기둥의 최상단 구간15/그 아래6 근사. 블록광 플러드필/AO가 없으므로 가까운 청크와 조명/텍스처 상세도 차이가 있다. 일반 청크의 조명 데이터는 변경하지 않는다.

## 세션·편집·메모리

동일 월드에서 시작 메뉴를 다녀와도 캐시 유지. F8재생성은 worker중지/join 후 생성기·LOD캐시 교체, GPU메시는지연폐기. 파일LOD캐시 없음. 사용자worldgen/settings는 패키징/진단으로 변경하지 않는다.

dirty_cell에서 현재 고체/유체를 별도 LOD 편집 기록으로 전달한다. 여러 변경은 컬럼/셀별 최신값으로 합쳐지고, 작업 스레드에서 해당 컬럼 기본생성+편집 적용→LOD/상위단계만 갱신한다. 원본 WorldEdits는 계속 권위 있는 실제월드 기록이다. 유체는 표시단계/종류/가득참 변화에만 LOD 변경이 필요하다. 거친캐시/정밀캐시 퇴거로 편집기록을 버리지 않는다.

CPU LOD 캐시 전체예산512MiB 안에 데이터/트리/공유중인메시/요청목록과 진행중 작업 여유를 둔다. 기본 데이터목표256MiB/퇴거목표240MiB, 선택메시48MiB 상한, 참조중인 메시 메모리는 atomic 공유계수로 렌더pending/active까지 집계한다. 오래되고 먼 세부 캐시부터 퇴거하며 거친부모를 우선 보존한다. 극단적으로 복잡한 지형에서도 예산을 우선하는 추가 퇴거가 있다. 선택 메시가 예산을 넘으면 먼 타일 표시가 제한될 수 있으며 F3 캐시한도로 알린다. 이는 전체게임프로세스512MiB 제한이 아니다.

GPU면버퍼256MiB 예산은 지연폐기 대기 버퍼도 포함한다. descriptor/작은 coverage버퍼/renderer공용staging·드라이버할당 여유는 이 수치와별도. 재사용불가능한메시는프레임펜스후반환. F3 CPU캐시는컨테이너메타데이터일부를추정하므로Windows RAM 수치와동일하지않다. 손실하면안되는 세션편집기록은 캐시퇴거 예산과 분리하고 F3별도MiB로표시한다.

## 설정과 검증

GameSettings schema9, graphics.lod 기본true / graphics.lod_distance 기본128·16..256. schema1..8은메모리에서새기본을추가하고파일은사용자가옵션을변경할때만저장. 시작/일시정지 옵션→화면에서조절. 원거리반경이일반반경보다작으면실효반경은일반반경.

검증결과는 docs/verification.md 최신 LOD절. 일반자동테스트/CTest/합성입력/CU는추가하지않는다. 격리 CLI 정지장면·성능기록·자체스크린샷만사용했다. 기존 GPU profile의steady는일반컬럼기준이므로LOD생성중의CSV도포함될수있다. 본실행결과를LOD완료후고정장면성능으로오인하지않는다. 이번에키보드/메뉴조작·이동경계·블록편집/재생성의상호작용을실제입력으로검증하지않았으며소스흐름을검토했다.

## 물 반사 연결 정정

- 업로드 조각(최대1MiB) 내부 면을 고체/물 두 구간으로 정렬한다. 별도 영구 면 복사/반사 이미지/원거리 노이즈 생성은 없다. 일반 고체 패스는 고체만, F4는 전체, 그림자는 기존 두 층에 맞춰 각 구간만 그린다.
- WaterEffects에 LOD 전용 geometry/layout 변형을 추가하고 water.frag/water_ssr.frag 소스를 LOD_WATER 정의로 재사용한다. coverage 마스크와 정점 형상을 공유하므로 고체/물/그림자/물깊이의 경계가 동일하다. 기존 물 반사/노멀/수심 옵션을 그대로 따른다.
- 하나의 opaque snapshot에 근거리/LOD 지형을 모두 담고 하나의75% SSR 타깃에 양쪽 물을 그린다. 물 수면 자신은 snapshot에 들어가지 않는다. SSR 최대이동거리는 max(근거리,LOD거리), 기존1024블록 상한 유지. depth<0.99994 임의절삭을 depth<1로 수정하여 실제 far plane 안쪽 먼 지형도 반사에 참여한다. 화면 밖 정보는 기존 하늘/구름 보완이며 SSR 한계는 유지한다.
- LOD 수면 색은 근거리 물보다 먼저 그리며 nearest depth를 기록해 순서가 다른 LOD 타일/뒷면이 앞 수면을 덮지 않게 한다. 불투명 배경 깊이는 별도 snapshot/SceneEffects opaque_depth에 보존되어 SSR/굴절은 수면 기록 전 지형을 사용한다. 이후 일반 물과 최종 물 깊이/구름/수중/대기/TAA를 합성한다.
- 기존 픽셀 발자국 기반 작은 노멀 감쇄를 공유하고 하이라이트의 medium/small 성분에도 적용한다. 줌에서는 실제 픽셀 크기에 따른 셰이딩 차이는 있을 수 있으나 LOD 메시/생성 상세도는 변하지 않는다.

## F4 LOD 단계 표시

후속 사용자 실시로 와이어프레임 제거. WorldView::lod_debug_/toggle_lod_debug()는 표시만 전환하고 TAA이력을 무효화한다. 모든 면은6정점 triangle list이며 정점셰이더의12정점 선변환과 플레이어선파이프라인을 삭제했다. 기존 SceneEffects effects.w는 이제 LOD디버그 상태로서 그림자/물효과/하늘효과/안개/블룸/톤매핑/TAA를 우회한다. 원래 설정파일을 수정하지 않는다.

실제청크는 물/얼음포함회색(.55), 플레이어몸체는흰색. LOD는 실제업로드·표시중인각타일의 step=2^level로색을정하며 생성요청/거리목표가아니다. coarse부모대체도그부모색으로표시. 공유 C++ lod_debug_palette를 Coverage.palette와 ImGui범례에 사용한다. 단색LOD는모든재질/물면을같은깊이검사로표시,법선/조명/재질과무관. 타일local좌표가XZ범위경계와만나는곳에픽셀폭약1의검은선. 블록경계·삼각형대각선·가려진외곽선을그리는것은아니다. 세로벽에서고정좌표축전체가검어지지않도록화면미분0축을제외한다.

우측범례는F3없이도보이며 F3가있으면핫바위로배치한다. 작은창에서F3우측문구가범례와겹치면그영역의F3하단을clip한다. 범례2열,실제청크+LOD0..9/1..512블록기둥크기를표시한다. F4해제시범례와clip제약을해제한다. --lod-debug는명시적CLI시작상태일뿐단축키합성이나자동테스트경로가아니다.
