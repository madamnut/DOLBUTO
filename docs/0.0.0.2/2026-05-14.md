## 결정 사항
- 저장/로드, 청크 로딩, 지형 생성, 지형 메싱은 렌더러의 핵심 책임이 아니므로 각각 전용 world/client subsystem으로 분리한다.
- `main.cpp`는 프로세스 진입점, GLFW/window 생성, 최상위 예외 처리만 담당하고, 게임 실행 흐름은 `GameClient`가 맡는다.
- `Renderer`는 Vulkan/GPU 리소스와 화면 출력에 집중하고, 게임 상태/월드 상태/저장/입력 규칙은 렌더러 밖으로 이동시킨다.
- UI 수명주기와 문서/이벤트 소유권은 `UiSystem`이 맡고, Vulkan UI 렌더링 backend는 아직 렌더러 쪽에 둔다.
- `WorldRuntime`은 runtime chunk storage의 단일 소유자가 되고, 렌더러는 필요한 경계에서만 world runtime을 호출한다.
- `ClientWorldRuntime`은 월드 전환과 terrain job 상태 조율을 담당하고, 렌더러는 GPU 설치와 시각 효과 같은 렌더 의존 결과만 처리한다.
- terrain render chunk storage는 `TerrainRenderPath` 내부 구현 세부사항으로 둔다.
