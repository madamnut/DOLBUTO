# 2026-05-17

## 작업 기록
- `assets/data/test/groundness_test.html`에 `GND`, `SMTH`, `W`, `PV`, `baseNoise`, `landBase`, `reliefAmount`, `ridgeMask`, `valleyMask`, `detailRelief`, `ridgeContribution`, `valleyContribution`, `VAL` 표시 모드를 추가했다.
- 테스트 HTML의 식은 `VAL = landBase + detailRelief + ridgeContribution - valleyContribution`로 두었고, 현재 게임 내 terrain formula와는 분리했다.
- 게임 내 높이 공식에서 PV baseline/influence를 제거했다. weirdness/PV 샘플링은 진단과 이후 강 mask 작업을 위해 유지했다.
- 현재 terrain value를 `GroundnessBaselineLUT(GND) + baseNoise * GroundnessInfluenceLUT(GND) * SmoothnessInfluenceLUT(SMTH)`로 정리했다.
- `smoothness_baseline_lut.json`과 `smoothness_baseline_lut.bin`을 제거했다. Smoothness는 이제 `smoothness_influence_lut`를 통해서만 기여한다.
- Groundness/Smoothness/Weirdness/PV 디버그 값을 `TERRAIN:` 라인에서 확인할 수 있도록 정리했다.
- Groundness와 baseNoise의 seed/config 사용 경로를 맞춰, 디버그 표시와 실제 terrain generation이 같은 월드 seed를 사용하도록 수정했다.
- PV 관련 LUT 초안을 만들고, 이후 강/능선 보정축으로 사용할 수 있도록 샘플링 경로를 유지했다.

## 결정 사항
- Groundness는 바다/해안/육지의 큰 성향을 만들고, Baseline은 terrainValue 기준값, Influence는 local baseNoise의 영향력으로 사용한다.
- Smoothness는 높이대를 직접 덮어쓰지 않고 baseNoise의 거칠기와 진폭을 조절하는 축으로 사용한다.
- PV는 당장 높이 공식의 핵심축으로 쓰지 않고, 낮은 PV는 골짜기/강 후보, 높은 PV는 능선/산맥 후보를 만드는 약한 보정축 후보로 남긴다.
- 테스트 HTML은 실험용 식을 빠르게 비교하는 용도로 두고, 게임 내 공식과 혼동하지 않도록 문서와 디버그 명칭을 분리한다.

## 이슈
- PV를 실제 높이에 반영하는 방식은 별도 검토가 필요하다.
