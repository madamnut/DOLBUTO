# 2026-05-21

## 작업 기록
- block light 채널을 활성화했다. packed light의 하위 4비트를 block light로 사용하고, 블록 정의의 `lightEmission` 값을 원천으로 local/resolve light 전파에 포함한다.
- 테스트용 `glowing_rock` 블록을 추가했다. 텍스처는 기존 `rock`을 재사용하며 `lightEmission = 15`를 가진다. 게임 중 `M` 키로 우클릭 배치 모드를 `rock`/`glowing_rock` 사이에서 전환한다.
- terrain/fluid shader는 `max(skyLight * skyBrightness, blockLight)`를 연속 light curve에 넣어 최종 밝기를 계산하도록 바꿨다.
- 하늘색 디버깅용으로 게임 화면에서 `[`/`]` hold 입력을 추가했다. `[`는 하루 안의 `worldTicks`를 해가 뜨는 방향으로 되감고, `]`는 해가 지는 방향으로 빠르게 진행시켜 sky shader와 sun/moon sprite 위치를 함께 확인할 수 있게 했다.
- 고정 scene clear color 대신 `SkyRenderPath`와 `sky.vert/sky.frag` 기반 fullscreen sky pass를 추가했다. sky shader는 카메라 view direction, sun direction, world up dot 값을 이용해 낮/일출/일몰/밤 하늘 그라데이션과 태양 방향 glow를 계산하고, 기존 sun/moon sprite 렌더링은 그 위에 유지한다.
- 블록 편집 후 skylight 갱신을 subchunk boundary 전파 방식으로 바꿨다. `WorldRuntime::resolveEditedSkyLightAtWorld`가 편집된 subchunk에서 시작해 6방향 인접 subchunk의 boundary light를 seed로 읽고, face light가 바뀐 경우에만 인접 subchunk를 dirty queue에 넣는다.
- `setBlockAtWorld`는 block 수정 후 해당 청크의 `localLight` cache만 갱신하고, edited mesh rebuild 경로가 바뀐 resolved-light subchunk들을 추가로 mesh rebuild 대상에 포함하도록 연결했다.
- 청크 생성 상태를 `Empty -> TerrainSourceReady -> LocalLightReady -> LightResolved -> Meshed` 흐름으로 정리했다.
- terrain job을 `BuildTerrainSource`, `ResolveFeatures`, `ResolveLight`, `BuildChunkMesh` 단계로 분리했다.
- `ResolveFeatures`는 3x3 `TerrainSourceReady` 입력 view에서 center 청크에 닿는 feature만 적용하고, 같은 worker 단계에서 local skylight까지 계산해 `LocalLightReady`를 반환하도록 했다.
- `ResolveLight`는 center와 동서남북 `LocalLightReady` 청크의 `localLight` face를 읽어 boundary propagation만 수행한 뒤 center 청크 resolved light만 반환하도록 했다.
- 렌더 요청 시 `Meshed`, `LightResolved`, `LocalLightReady`, `TerrainSourceReady` 목표 범위를 먼저 설정하고, 실제 job 삽입은 frontier scheduler가 맡도록 했다.
- mesh/light cascade의 target 범위를 실제 의존성 모양에 맞춰 줄였다. mesh 요청은 3x3 `LightResolved`, radius 2 square without corners `LocalLightReady`, radius 3 square without corners `TerrainSourceReady`만 요청한다.
- `blocks.json`과 `fluids.json`에 `lightAttenuation`을 추가하고, skylight 계산이 블록/유체 ID 하드코딩 대신 content에서 만든 attenuation table을 읽도록 연결했다.
- source-only 청크가 저장 로드 완료 후 생성 job으로 재개될 수 있도록 `sourceTicket`을 추가했다.
- 구형 런타임 feature write 전파 경로와 `BuildFeaturing/FinalizeFeatures/FeaturePlanned` 명칭을 클라이언트 조율 코드에서 제거했다.
- 청크별 `targetGenState`를 추가해 렌더 요청 시 목표 상태 범위를 먼저 칠하고, `scheduleAround`가 승급 가능한 frontier만 job queue에 넣도록 바꿨다.
- snapshot load 완료 시 전체 request cascade를 다시 호출하지 않고 완료 청크 주변 frontier만 재검사하도록 바꿨다.
- `TerrainSourceReady` 단계에서 column별 지형 높이/표면 Y와 deterministic tree 후보를 source checkpoint로 캐시하도록 했다.
- `ResolveFeatures`가 fresh source 청크의 tree 후보 cache를 바로 사용하고, 저장 파일에서 복원된 청크는 block scan으로 복원한 terrain source cache를 fallback으로 사용하도록 했다.
- `ResolveLight`가 3x3 `ChunkData` 전체 복사본을 만들지 않고, center local light buffer와 4방향 이웃 face만 사용하도록 바꿨다.
- 단일 청크 skylight 재계산과 center skylight resolve가 같은 local skylight helper를 사용하도록 정리했다.
- `ChunkSourceData`, `ChunkBlockData`, `ChunkLightData`, `ChunkDerivedCache` 역할 타입을 도입해 ChunkData 내부 산출물 분리 기준을 코드에 명시했다.
- `ClientWorldRuntime`, `ClientTerrainCoordinator`, `TerrainJobSystem`, `ClientTerrainJobProcessor`, `WorldRuntime`, `SaveSystem`의 상태/작업 경로를 `LocalLightReady` 단계에 맞게 재배선하고 독립 `BuildLocalLight` queue를 제거했다.
- terrain 완료 후 frontier 재검사를 단계별 dependent shape로 제한했다. source 완료는 local-light 3x3, local-light 완료는 light center + 4방향, light 완료는 mesh 3x3만 검사한다.
- skylight BFS 큐 노드를 `x/y/z + light`에서 `block index + light`로 줄이고, 전파 시점에만 index를 `x/z/y`로 디코딩하도록 바꿨다.
- skylight BFS 큐 컨테이너를 `std::queue`에서 `ChunkBlockCount`만큼 미리 reserve한 vector/head-index queue로 바꿔 push/pop 중 컨테이너 오버헤드를 줄였다.
- skylight BFS inner loop에서 `blockIndex(nx, ny, nz)`와 `attenuationForCell()` 반복 호출을 제거했다. 청크별 attenuation cache를 먼저 만들고, 전파는 `index +/- 1/16/256` offset과 배열 조회로 처리하도록 local/resolve 공통 helper를 정리했다.
- 이동 중 프레임 hitch 원인 추적을 위해 좌하단 `PERF MAX [R]` 디버그 블록을 추가했다. 이후 표시 항목을 `T_DONE` 내부 분석용 `TD_DRAIN`, `TD_TRACK`, `TD_INSTALL`, `TD_MARK`, `TD_STATS`, `TD_RETIRE`, `TD_UNLOAD`, `TD_MESHES`, `TD_REFRESH`, `TD_UNLOADED`로 교체했다.
- `TD_DRAIN`이 과도하게 큰 것을 확인하기 위해 좌하단 표시를 다시 `TD_POP`, `TD_HANDLE`, `TD_LOAD`, `TD_TERRAIN`, `TD_MESH`, `TD_SAVEQ`, `TD_SOURCE`, `TD_LIGHT`, `TD_BUILDMESH`, `TD_POP_CNT`, `TD_TERR_CNT`, `TD_LOAD_CNT`로 교체했다.
- `TD_LOAD` 내부 병목 확인을 위해 좌하단 표시를 `TL_FINISH`, `TL_SNAPSHOT`, `TL_INSTALL`, `TL_RESUME`, `TL_TOTAL`, `TL_COUNT`, `TD_POP`, `TD_HANDLE`, `TD_TERR_CNT`, `TD_POP_CNT`로 교체했다.

## 결정 사항
- 3x3은 job의 처리 단위가 아니라 read-only 입력 view다. 모든 terrain worker 결과는 center 청크 하나만 산출한다.
- feature, light, mesh 경계 안정성을 위해 요청 범위는 단계별 의존성으로 확장되지만, 5x5/7x7 같은 큰 묶음을 하나의 job에서 처리하지 않는다.
- 요청 함수는 의존 단계를 즉시 재귀 실행하지 않고 target status만 올린다. job 삽입은 scheduler가 current/target status와 이웃 조건을 보고 수행한다.
- 저장 포맷의 incoming feature slot 필드는 전환기 호환 필드로 남겨두되, 새 생성 경로는 여기에 의존하지 않는다.
