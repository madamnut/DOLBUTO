## 결정 사항
- render path는 GPU resource lifetime과 draw submission을 맡고, world/gameplay runtime은 렌더러 밖에서 상태와 규칙을 소유한다.
- `Renderer`는 visual/audio side effect, Vulkan/UI presentation, GPU install/draw handoff만 담당하고 gameplay state를 직접 소유하지 않는다.
- `ClientGameplayRuntime`은 inventory, dropped item runtime, block breaking state의 소유자다.
- `ClientUiBridge`는 UI 표시/입력과 gameplay state 사이의 adapter다.
- `ClientContent`는 JSON content parsing과 definition map 소유자이며, 렌더러는 로딩된 content를 소비한다.
- `RendererAssetStore`는 GPU asset lifetime의 소유자다.
- `TerrainGeometryBuilder`는 terrain CPU geometry 생성 책임을 가진다.
- `ClimateSystem`과 `ClimateOverlayTextureBuilder`는 climate 계산과 overlay pixel 생성을 렌더러 독립 영역으로 둔다.
- `ClientWorldRuntime`, `ClientTerrainJobProcessor`, `ClientTerrainCoordinator`, `ClientTerrainCompletionHandler`, `ClientTerrainSceneRuntime`은 terrain request/completion/lifecycle을 단계별로 나눠 맡는다.
- `ClientRuntime`은 `GameClient`가 접근하는 상위 facade이고, `ClientRenderRuntime`은 렌더러 접근과 frame 변환을 감추는 adapter다.
- `Renderer.cpp`는 새 기능을 추가하는 장소가 아니며, 책임별 파일로 분리된 상태를 유지한다.
- `Renderer.h`는 public facade와 소유/배선만 남기는 방향으로 계속 축소한다.
