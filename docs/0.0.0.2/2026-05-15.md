## 결정 사항
- Terrain render chunk storage shape is an implementation detail of `TerrainRenderPath`.
- `Renderer` remains the bridge for terrain job completion timing, but render chunk install, replacement, retirement, GPU upload, and draw traversal stay inside `TerrainRenderPath`.
- Player mesh uses a host-visible indexed vertex buffer path and is owned separately from terrain render chunks by `PlayerMeshRenderPath`.
- Block break particles are renderer-local visual effects owned by `ParticleRenderPath`; `Renderer` only supplies block texture layers, breaking state, camera/pipeline handles, and terrain collision callback.
- Dropped item runtime work is owned by `DroppedItemRuntime`; `RendererDroppedItems.cpp` remains only the dropped item draw coordinator.
- Item sprite extrusion is an asset/render helper responsibility owned by `ItemSpriteMeshBuilder`, not by the dropped item world bridge.
- Dropped item runtime ownership is now `DroppedItemRuntime`; render candidate policy is owned by `DroppedItemRenderCollector`; GPU upload/draw ownership is `DroppedItemRenderPath`.
- Client gameplay runtime ownership is `ClientGameplayRuntime`; Renderer should keep visual/audio side effects and Vulkan/UI presentation work, not direct gameplay state ownership.
- Client UI bridge ownership is `ClientUiBridge`; Renderer keeps RmlUi Vulkan backend work and passes viewport/input data into the bridge.
- Client content ownership is `ClientContent`; Renderer should consume loaded content definitions without parsing JSON or owning item/block definition maps directly.
- Renderer GPU asset ownership is `RendererAssetStore`; Renderer should request creation/destruction and pass asset references into render paths.
- Terrain CPU geometry ownership is `TerrainGeometryBuilder`; Renderer remains responsible for job timing, runtime chunk coordination, and GPU install/draw handoff.
- Text rendering ownership is `TextRenderPath`; Renderer should provide display strings and draw timing, not own font atlas generation or text vertex upload.
- Screen presentation ownership is `ScreenPresentation`; Renderer should own render pass boundaries and timing, while screen-space presentation policy stays outside the renderer core.
- Climate rule ownership is `ClimateSystem`; Renderer can request climate values or chunk climate population, but noise sampling and climate formulas must stay renderer-independent.
- Climate overlay pixel ownership is `ClimateOverlayTextureBuilder`; Renderer should only create/upload the Vulkan texture from the generated pixel buffer.
- Debug display state ownership is `DebugOverlayText`; Renderer should provide source values and draw timing, not own every debug string field directly.
- Save snapshot and saved snapshot restore ownership is `ClientWorldRuntime`; Renderer should not construct runtime chunk snapshots directly.
- Feature slot propagation ownership is `ClientWorldRuntime`; Renderer should consume propagation results to enqueue visual/terrain boundary work.
- World-only terrain job processing ownership is `ClientTerrainJobProcessor`; Renderer should keep mesh job processing only while it still depends on render asset/material inputs.
- Render-dependent terrain CPU mesh orchestration ownership is `RendererTerrainMeshBridge`; Renderer should keep GPU install/draw ownership and pass CPU mesh results into `TerrainRenderPath`.
- Terrain request orchestration ownership is `ClientTerrainCoordinator`; `ClientTerrainSceneRuntime` should connect worker enqueue, chunk-load enqueue, and mesh-ready callbacks rather than letting Renderer own terrain request rules.
- Terrain completion flow ownership is `ClientTerrainCompletionHandler`; Renderer should not directly own load/chunk/mesh completion save/install/retry policy.
- Terrain scene lifecycle ownership is `ClientTerrainSceneRuntime`; Renderer should keep only render storage reserve/retire, render-dependent mesh building, GPU mesh install, and dropped-item visual tracking side effects.
- Game scene lifecycle ownership is `ClientSceneLifecycle`; Renderer should not own scene load/unload policy beyond renderer-specific hooks.
- GameClient-facing runtime ownership is `ClientRuntime`; `GameClient` should not call `Renderer` directly for gameplay, scene, inventory, UI, or world query actions.
- `ClientRuntime` should expose role-based access surfaces rather than growing into a flat list of scene/gameplay/UI/render methods.
- Renderer-independent client runtime queries should stay in `ClientRuntime` and should not be routed through `ClientRenderRuntime`.
- Renderer-facing adapter ownership is `ClientRenderRuntime`; renderer bridge access and `RendererFrame` conversion should stay behind this adapter while `ClientRuntime` grows into the client runtime system boundary.
- `ClientFrame` is the GameClient-facing frame DTO; `RendererFrame` should remain behind `ClientRenderRuntime`.
- Renderer frame-loop ownership is `RendererFrameLoop.cpp`; the former `Renderer.cpp` responsibilities have been moved into named lifecycle, frame-loop, Vulkan core, bridge, and draw translation units.
- Vulkan core setup ownership is split across `RendererVulkanContext.cpp`, `RendererSwapchain.cpp`, and `RendererPipelines.cpp`; `Renderer.cpp` should no longer be the home for new Vulkan setup functions.
- Renderer gameplay, terrain runtime, and scene/debug transition ownership is now isolated in bridge translation units; new non-draw runtime glue should not be added back to `Renderer.cpp`.
- `Renderer.cpp` no longer exists as an implementation unit; new Renderer behavior should be placed in the matching responsibility file or a new named render subsystem.
- Renderer shared render DTO/type ownership is `RendererTypes.h`; `Renderer.h` should keep shrinking toward the public facade plus ownership wiring rather than storing implementation-local type definitions.
- Vulkan handle ownership is `RendererVulkanState`; `Renderer.h` should not regain individual Vulkan handle members.
- Client runtime transition state ownership is `ClientRuntimeState` under `ClientRuntime`; `Renderer.h` should not regain direct gameplay/world/UI/audio/config member fields or own this state directly.
- RmlUi Vulkan backend ownership is `RendererRmlUiBackend`; `Renderer` should not regain direct `Rml::RenderInterface` inheritance.
- Renderer gameplay bridge ownership is `RendererGameplayBridge`; `Renderer.h` should not regain direct block interaction helper declarations or gameplay side-effect implementation details.
- Renderer terrain runtime bridge ownership is `RendererTerrainRuntimeBridge`; `Renderer.h` should not regain terrain load/job/unload/edit-mesh/stat helper declarations.
- Renderer scene lifecycle, config, audio, diagnostics, and climate overlay work should stay in responsibility-specific translation units rather than returning to a combined scene/debug file.
- Renderer diagnostics ownership is `RendererDiagnosticsBridge`; `Renderer.h` should not regain selected block/climate/debug/performance/VRAM helper declarations.
- Renderer audio ownership is `RendererAudioBridge`; `Renderer.h` should not regain audio init/update/sound helper declarations.
- Renderer private implementation declarations should stay in `RendererVulkanMethods.inc` and `RendererRenderMethods.inc`; `Renderer.h` should remain focused on public API and ownership wiring.
- Renderer config/content ownership is `RendererConfigBridge`; Renderer method declarations should not regain content/config/height LUT load helpers.
- Renderer UI runtime ownership is `RendererUiRuntimeBridge`; Renderer method declaration fragments should not regain UI input/action/world-list/inventory/RmlUi helper declarations.
- Renderer scene lifecycle ownership is `RendererSceneLifecycleBridge`; Renderer method declarations should not regain scene load/unload wrappers.
- `ClientRenderRuntime` should use renderer-owned bridge objects for scene/gameplay/UI/diagnostics handoff instead of adding facade-only Renderer wrapper methods.
