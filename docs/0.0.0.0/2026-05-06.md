# 2026-05-06

## 작업 기록
- 우하단 디버그 텍스트에 누적 피크 프로파일러를 추가했다. 프로그램 시작 후 5초 뒤부터 샘플링하며, `R` 키로 누적 피크를 초기화한다.
- 누적 피크는 FRAME, UPDATE, JOB MAIN, UPLOAD, UNLOAD, RETIRE, SAVE ENQUEUE 기준으로 분리해서 표시한다.
- 청크 로딩 요청을 `wantRender -> wantMesh -> wantFull -> wantFeaturing` 의존성 파생 방식으로 개편했다.
- 로딩 반경 처리는 정렬된 렌더 오프셋을 seed로 넣는 역할만 하고, 주변 데이터/feature source 요청은 각 렌더 청크의 의존성 함수가 파생시키도록 변경했다.
- terrain 잡에 거리 기반 priority와 삽입 sequence를 추가하고, 워커가 `거리 -> 단계 -> 삽입 순서` 기준으로 다음 잡을 선택하도록 변경했다.
- 좌하단 디버그 텍스트를 새 청크 파이프라인 기준으로 수정했다. 원하는 render/feature/data 수, 청크 상태 분포, render missing, 단계별 queue/done 수를 표시한다.
- 좌하단 디버그 텍스트의 축약 라벨을 풀네임으로 바꿔 `RENDER`, `FEATURE`, `DATA`, `BUILD`, `FINALIZE`, `MESH` 의미가 바로 보이도록 수정했다.
- `RuntimeChunk`와 저장 snapshot의 feature 수신 필드를 `incomingFeatureSlots`, `incomingFeatureMask`로 명확히 바꾸고, outgoing publish 추적과 저장 dirty 필드명도 새 파이프라인 기준으로 정리했다.
- 청크 내부의 build/finalize/mesh 큐 상태를 `bool` 대신 현재 `terrainGeneration` 기준 티켓 필드로 바꿨다.
- 언로드된 feature job 결과가 현재 필요한 이웃 청크에는 즉시 전달되고, 필요 없는 이웃 청크에는 저장 큐로 넘어가도록 저장/로드 경로를 보정했다.
- 청크 저장 payload 끝에 `revision`을 기록/복원하도록 수정해서, 저장 후 재로드된 Full 청크의 무변경 재저장 스킵 기준이 유지되도록 했다.
- 이동 중 디버그 텍스트 vertex 수가 기존 버퍼 한도를 넘으면 렌더 루프에서 예외가 발생하던 문제를 막기 위해 텍스트 vertex 버퍼 한도를 늘리고, 한도를 넘는 경우 해당 배치를 그리지 않도록 했다.
- 청크 로딩 중심은 2x2 청크 그룹 기준으로 유지하되, 실제 로딩/메싱/렌더 요청은 개별 청크 단위로 유지하도록 정리했다.
- 사용자 편집으로 dirty 처리된 청크 snapshot은 강제 저장하고, 늦게 도착한 비편집 생성 결과가 기존 Full 저장본을 낮은 revision이나 Featuring 상태로 덮어쓰지 못하게 막았다.
- 좌하단 디버그 텍스트에 저장 큐/저장 캐시, 저장 완료/실패, 로드 pending hit/region hit/miss 지표를 추가했다.
- 청크 메시 교체와 블럭 편집 리메시에서 기존 GPU 버퍼를 즉시 파괴하지 않고 retired terrain queue로 넘겨 지연 파괴하도록 수정했다.
- 저장 디버그의 완료 수를 청크 본체 저장과 feature-slot 저장으로 분리해, 초기 생성 경계에서 발생하는 feature 저장 job이 청크 저장처럼 보이지 않도록 했다.
- deterministic feature는 source 청크가 다시 생성될 때 재현 가능하므로, 현재 로딩 대상이 아닌 외곽 청크의 incoming feature slot을 미리 저장하지 않도록 변경했다.
- 렌더 범위 바깥 2청크 두께까지 `RuntimeChunk` keep-alive 풀을 확보해, 기존 파생 로직이 발생시키는 feature write target이 런타임에 존재할 수 있도록 했다.
- 언로드/종료 저장 job이 블럭 배열을 복사하지 않고 `ChunkData` shared pointer를 들고 가도록 바꿔, 언로드 시 메인스레드 blocks 복사를 제거했다.
- 새로 생성되어 아직 세이브파일 backing이 없는 청크는 저장 대상으로 유지하고, 세이브파일에서 로드된 뒤 편집되지 않은 청크만 저장 스킵되도록 `hasSavedBacking` 상태를 추가했다.

## 결정 사항
- 순간 스파이크 분석은 현재값 대신 프로그램 시작 안정화 이후 누적 최대값을 유지하는 방식으로 확인한다.
- feature 전파는 같은 로딩 세대에서 청크당 한 번만 수행한다.
- 메인스레드는 전체 feature/finalize/mesh 상태를 반복 스캔하지 않고, `wantRender` seed 입력과 완료 이벤트에서 발생하는 주변 `tryFinalize`/`tryMesh`만 처리한다.
- 가까운 청크가 먼저 완성되도록 파생 작업은 원래 render target의 priority를 상속한다.
- 좌하단 프로파일링 영역은 임시 병목 확인 공간이므로, 현재 로딩 파이프라인에서 청크가 어느 상태에 머무는지 확인 가능한 지표를 우선 표시한다.
- 저장 대상 feature 데이터는 target 청크가 받은 incoming feature이며, outgoing feature는 런타임 캐시로 보고 필요 시 deterministic하게 다시 만든다.
- 큐 중복 방지는 청크별 queued ticket이 현재 로딩 세대와 같은지만 확인한다. 따라서 새 로딩 요청 때 모든 런타임 청크의 큐 플래그를 강제로 초기화하지 않는다.
- 현재 세대에서 더 이상 필요 없는 source 청크의 feature 결과라도, target 청크가 현재 로딩 범위에 있으면 저장 파일로 우회하지 않고 런타임 청크에 직접 적용한다.
- Full 청크 저장 데이터는 `revision`까지 포함한 상태를 기준으로 clean revision을 판단한다.
- 디버그 텍스트는 진단용 표시이므로, 텍스트 버퍼 한도를 넘는 상황에서 게임을 중단시키지 않는다.
- 플레이어 중심 판정은 항상 2x2 청크 그룹 기준이지만, 실제 청크 데이터와 렌더링은 개별 청크 단위로 처리한다.
- 저장된 Full 청크는 사용자 편집 snapshot이 아닌 이상 더 낮은 revision의 생성 결과나 중간 생성 상태로 다운그레이드하지 않는다.
- 저장/로드 지표는 20Hz 디버그 샘플링 시점에 갱신하며, 저장 큐 크기와 로드 경로별 누적 횟수를 우선 확인한다.
- 렌더 중인 terrain mesh 버퍼는 이전 프레임 커맨드 버퍼가 참조할 수 있으므로, 교체/언로드 시 `MaxFramesInFlight + 1` 프레임 뒤에 파괴한다.
- `SAVE CHUNK/FEATURE/FAILED`에서 CHUNK는 블럭 데이터가 포함된 snapshot 저장, FEATURE는 `Empty + incoming feature` 같은 feature-slot 저장 job을 의미한다.
- 로딩 범위 밖 feature write는 즉시 저장하지 않는다. 현재 필요한 target 청크가 있을 때만 런타임으로 전달하고, 나머지는 나중에 source 청크가 다시 로딩될 때 재생성한다.
- 렌더 범위가 `n x n`일 때 런타임 청크 데이터 풀은 `(n + 4) x (n + 4)`로 유지하되, 추가 keep-alive 청크에는 render/mesh/full/featuring 요청을 직접 넣지 않는다.
- 저장 worker는 `SaveChunkSnapshot`의 `chunkData` 포인터를 통해 블럭 배열을 읽고, 저장 완료 후 같은 revision의 pending save cache를 제거한다.
- 저장 판정은 `!hasSavedBacking || dataDirtyForSave` 기준이다. 저장 완료 또는 region 로드로 backing이 확인된 청크는 편집 전까지 재저장하지 않는다.
