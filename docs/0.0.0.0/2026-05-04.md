## 작업 기록

- 블럭 편집 후 리메시가 청크 전체 32개 서브청크를 다시 만들던 흐름을 수정했다.
- 편집된 블럭이 포함된 서브청크와 경계 영향을 받는 인접 서브청크/청크만 즉시 리메시하도록 변경했다.
- 블럭 편집 리메시는 청크 로딩용 `18 x 512 x 18` 메싱 입력을 만들지 않고, 편집 서브청크 주변 `18 x 18 x 18` 임시 입력만 만들도록 분리했다.
- 청크 로딩 순서를 링 순회 방식에서 중심 2x2 청크 그룹 기준 거리순 오프셋 테이블 방식으로 변경했다.
- 블럭 정의 JSON과 런타임 블럭 정의 테이블에 방향성 여부를 나타내는 `directional` 필드를 추가했다.
- 전역 좌표 기반 `worldRandom8` 해시 랜덤을 추가했다.
- 각 월드 컬럼의 맨 아래 bedrock 두께를 `worldRandom8` 기반 1~4블럭으로 생성하도록 변경했다.
- `directional`이 false인 블럭의 윗면 텍스처는 `worldRandom8` 기반 4방향 회전을 적용하도록 변경했다.
- 지형 생성 시 가장 윗블럭이 grass인 컬럼에는 70% 확률로 그 위에 plant 블럭을 배치하도록 추가했다.
- `cross` 렌더 타입 블럭을 X자 형태의 양면 쿼드로 메싱하도록 추가했다.
- terrain fragment shader에서 알파값 0.5 미만 픽셀을 discard해 plant/leaves 같은 cutout 텍스처가 뚫려 보이도록 했다.
- 블럭 정의 JSON과 terrain vertex에 `mipDistanceScale`을 추가해 블럭별 밉맵 전환 거리를 조정할 수 있도록 변경했다.
- 블럭 텍스처 어레이 로딩 시 `assets/textures/block/mip/<텍스처명>_mipN.png` 수동 mip 파일이 있으면 해당 mip level을 우선 사용하도록 추가했다.
- 블럭 텍스처의 누락된 mip level은 실행 중 직전 mip level에서 생성하고 `assets/textures/block/mip/` 폴더에 PNG로 저장하도록 추가했다.
- 생성된 mip PNG 저장은 직접 작성한 PNG writer 대신 `external/stb/stb_image_write.h`의 `stbi_write_png`를 사용하도록 변경했다.
- 밉맵 전환 기준을 `mipDistanceScale` 1.0일 때 64블럭 단위로 변경하고, 모든 블럭 텍스처의 `mipDistanceScale`을 1.0으로 맞췄다.
- 전역 식생 난수 구간을 plant `0~167`, tree `168~170`으로 분리했다.
- 나무 생성을 추가하고, trunk는 청크 내부에 직접 배치하며 청크 경계를 넘는 leaves는 feature contribution으로 분리했다.
- 청크 로딩 파이프라인을 `BuildChunkData -> MergeChunkFeatures -> BuildChunkMesh` 단계로 나누고, contribution 수집 후 merge 완료된 최종 청크만 `chunkData_`에 등록하도록 변경했다.
- 렌더 대상 청크 바깥에 데이터 전용 외곽 1청크 링을 추가하고, 외곽 링은 청크 데이터/feature contribution까지만 만들며 렌더 메시를 만들지 않도록 변경했다.
- 청크 로딩 메싱은 기존 `18 x 512 x 18` 임시 border 재생성 대신 중심 청크와 주변 8청크의 `ChunkData`를 직접 읽도록 변경했다.

- 청크 생성 파이프라인을 `Empty -> Featuring -> Full -> Meshed` 상태 기준으로 개편했다.
- 기존 `pendingFeatureMerges_`, `chunkData_` 중심의 암묵적 상태 관리를 제거하고, 청크별 `RuntimeChunk`가 `genState`, 데이터 포인터, feature 수신 슬롯, 수신 마스크, 잡 큐 플래그를 갖도록 변경했다.
- `BuildChunkData` 잡을 `BuildFeaturing` 잡으로 변경했다. 이 잡은 기본 지형/표층/plant 생성 후 자기 청크 내부 tree feature를 직접 적용하고, 이웃 8방향으로 보낼 feature write 목록을 생성한다.
- `MergeChunkFeatures` 잡을 `FinalizeFeatures` 잡으로 변경했다. 이 잡은 이웃 8방향 feature slot을 청크 데이터에 반영해 `Full` 상태로 승급한다.
- 렌더 요청 범위를 `render`, `feature source`, `feature receive record`로 분리했다. 렌더 범위는 실제 메시 대상, feature source 범위는 `Featuring` 목표, receive record 범위는 feature write를 받을 수 있는 빈 청크 레코드 확보용이다.
- feature write는 개별 복사 대신 `shared_ptr<vector<FeatureWrite>>` 슬롯 단위로 전달하도록 했다.
- 중심 청크는 `Full` 상태일 때만 메시 잡을 넣고, 메싱 경계 참조용 주변 8청크는 `Featuring` 이상 데이터가 있으면 사용할 수 있도록 했다.
- 저장 전용 워커 1개와 저장 큐를 추가했다.
- 청크 언로드 직전, 잡 결과가 도착했지만 현재 로딩 범위 밖인 경우, 그리고 종료 시 런타임에 올라온 모든 청크를 저장 큐에 넣도록 했다.
- feature 작업 결과가 주변 8청크로 전달될 때 target 청크가 언로드 범위라면 해당 feature slot을 저장 큐로 넘기도록 했다.
- region 파일은 `saves/world/regions/r.<regionX>.<regionZ>.region` 경로에 저장하고, 16x16 청크/4096바이트 섹터/sector 0 엔트리 테이블 구조를 사용하도록 했다.
- 청크 payload는 블록 데이터를 RLE로 기록하고, payload 전체를 LZ4 block 형태로 저장하도록 했다.
- 청크 로드 경로를 추가했다. 로딩 요청 시 저장 대기 중인 snapshot을 먼저 확인하고, 없으면 region 파일에서 payload를 읽어 RuntimeChunk로 복원한다.
- 로드된 `Full` 청크는 `savedCleanRevisions_`에 등록해, 편집 없이 다시 저장될 때 중복 저장을 스킵할 수 있게 했다.
- 로드된 청크가 나중에 feature source가 될 수 있도록, outgoing feature slot이 비어 있으면 deterministic 생성 규칙으로 지연 재생성하도록 했다.
- terrain 잡 큐를 `mesh`, `finalize`, `feature` 3개로 분할하고, 워커가 `Mesh -> Finalize -> Feature` 우선순위로 처리하도록 변경했다.
- `BuildFeaturing` 완료 후 주변 mesh 조건도 즉시 재검사하도록 해서, 경계 참조 청크가 뒤늦게 준비된 경우 인접 Full 청크가 메시 큐에 들어가지 못하는 문제를 수정했다.

## 결정 사항
- 블럭 상호작용 레이는 렌더링에서 실제로 보이는 시야 방향과 동일하게 `camera.forward()`의 Y 성분을 반전한 방향을 사용한다.
- 이동 입력 계산에 쓰는 카메라 방향은 기존 값을 유지하고, 블럭 상호작용과 3인칭 카메라 위치 계산에만 화면 기준 방향을 사용한다.
- 청크 로딩은 기존처럼 청크 전체 메시 잡을 사용하지만, 블럭 편집 리메시는 서브청크 단위 GPU 버퍼만 교체한다.
- 편집 위치가 X/Z 청크 경계나 Y 서브청크 경계에 닿으면 AO/면 컬링 갱신을 위해 해당 경계의 인접 단위도 함께 리메시한다.
- 청크 로딩 메싱은 중심 청크와 주변 8청크의 merge 완료 `ChunkData`를 읽어 경계를 처리하고, 블럭 편집 메싱은 현재 런타임 청크 데이터에서 작은 서브청크 경계 버퍼를 만들어 사용한다.
- 청크 로딩 오프셋 테이블은 로딩 지름이 바뀔 때만 다시 만들고, 각 오프셋은 중심 2x2 청크 그룹까지의 거리 제곱 기준으로 정렬한다.
- 같은 거리의 청크들은 별도 방향 우선순위를 두지 않고 테이블 생성 순서에 맡긴다.
- `directional`은 블럭 타입이 방향성을 지원하는지 여부만 나타내며, 개별 블럭 인스턴스의 실제 방향값 저장은 아직 추가하지 않는다.
- 완전 랜덤 값은 저장하지 않고 월드 좌표와 salt에서 다시 계산한다.
- 비방향성 블럭의 윗면 텍스처 회전은 내부적으로 0~3 값으로 계산해 0도, 90도, 180도, 270도 회전으로 사용한다.
- 윗면 회전값이 다른 면끼리는 그리디 메싱에서 병합하지 않는다.
- plant 배치는 grass 표면 위 1블럭 높이에 두며, 좌표 기반 `worldRandom8`로 약 70% 확률을 판정한다.
- cross 타입은 그리디 메싱 대상이 아니며 개별 블럭마다 두 장의 교차 평면을 양면으로 생성한다.
- `mipDistanceScale`은 0.0이면 밉맵을 끄고, 1.0이면 64블럭마다 밉맵을 전환하며, 2.0이면 128블럭마다 전환하는 식으로 해석한다.
- 현재 모든 블럭 텍스처는 `mipDistanceScale`을 1.0으로 둔다.
- `mipDistanceScale`이 다른 cube 면끼리는 그리디 메싱에서 병합하지 않는다.
- 수동 mip 파일은 `assets/textures/block/mip/rock_mip1.png`, `assets/textures/block/mip/rock_mip2.png` 같은 이름으로 둔다.
- 수동 mip level 사이에 빠진 level은 직전 mip level에서 자동 생성하고 같은 mip 폴더에 저장한다.
- 이미지 읽기는 `stb_image`, 이미지 쓰기는 `stb_image_write`를 사용하며, implementation은 `src/third_party`의 별도 cpp 파일에서 한 번만 정의한다.
- 식생 배치 난수는 같은 salt에서 0~255 값을 사용하며, 현재 plant는 0~167, tree 예정 구간은 168~170으로 둔다.
- 나무는 grass 위에서 생성되며 trunk는 grass 위 4칸, leaves는 그 위 3층으로 둔다. 꼭대기 leaves는 3x3이고 중심 trunk는 없다.
- feature 블럭 우선순위는 `trunk > leaves > plant > air`로 두며, 경계 contribution으로 들어온 leaves는 `air`와 `plant`만 덮어쓴다.
- 각 청크 데이터 생성 결과는 자기 포함 주변 3x3 target 청크에 대해 빈 것 포함 9개의 feature contribution을 반환한다.
- target 청크는 base chunk와 필요한 source contribution이 모이면 `MergeChunkFeatures` 잡으로 들어가고, merge 완료 후에만 `chunkData_`에 등록한다.
- merge 완료 이벤트에서 주변 3x3 청크만 `tryQueueMeshIfReady`로 검사하며, 전체 청크를 매 프레임 스캔하지 않는다.
- mesh job은 target이 렌더 대상이고 target 포함 주변 3x3 청크가 모두 `chunkData_`에 등록된 경우에만 큐에 넣는다.

- `TerrainSurface` 상태는 별도로 두지 않고 `Featuring`에 합친다.
- 일부 feature 수신 여부는 `genState`가 아니라 `receivedFeatureMask`와 8방향 `featureSlots`로 관리한다.
- `Full`은 게임플레이용 런타임 청크 데이터가 완성되어 메싱만 남은 상태로 정의한다.
- `Meshed`는 저장 시 `Full`로 낮춰 저장할 예정이며, 메시 자체는 저장하지 않는다.
- 저장 쓰기와 로드는 같은 region payload 포맷을 사용한다.
- 저장 워커는 범용 terrain job system에 섞지 않고 별도 큐와 1개 스레드로 둔다.
- region 파일은 기존 sector를 즉시 재활용하지 않고 새 payload를 append한 뒤 header entry만 최신 위치로 갱신한다.
- `Full`/`Meshed` 청크는 저장 시 feature slot을 비우고, `Meshed`는 `Full`로 저장한다.
- 저장된 `Full` 청크가 같은 revision으로 다시 저장 요청되면 중복 저장을 스킵한다.
- 로드 우선순위는 `pendingSaveSnapshots_` 메모리 snapshot, region 파일, 신규 생성 순서로 한다.
- 4개 terrain worker는 큐별 전담이 아니라 3개 공용 큐를 우선순위대로 소비한다.
- `BuildChunkMesh`는 `Full` 이상 청크에 대해서만 큐에 넣는다.
