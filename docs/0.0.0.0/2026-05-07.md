- 우하단 누적 피크 프로파일러를 `UPDATE` 세부 분석용으로 교체했다.

- `wantRender`/`wantMesh`/`wantFull`/`wantFeaturing` 경로에 상태 기반 빠른 종료를 추가해, 이미 렌더 가능한 청크가 의존성 요청을 다시 펼치지 않도록 했다.

## 결정 사항
- `WANT RENDER` 병목은 추정으로 수정하지 않고, 내부 단계별 누적 피크를 확인한 뒤 다음 최적화 대상을 정한다.
- 중심 청크 메싱에 필요한 주변 feature 준비 요청은 `wantFull()`에서만 담당한다.
- `ENSURE RUNTIME` 병목은 `ensureRuntimeChunk()` 내부 단계별 누적 피크를 확인한 뒤 최적화 대상을 정한다.
- region header cache는 저장 포맷을 바꾸지 않고, 같은 region 안의 여러 청크 로드 확인에서 파일 open/header read 반복을 줄이는 용도로 사용한다.
- 청크 로딩 중 `unordered_map`/`unordered_set` rehash로 인한 순간 스파이크를 줄이기 위해 reserve는 실제 런타임/렌더/feature 범위보다 약간 여유 있게 잡는다.
- terrain mesh는 생성/수정 시 업로드 비용보다 이후 여러 프레임의 GPU read 비용이 중요하므로 최종 버퍼를 `DEVICE_LOCAL`에 둔다.
- 같은 texture array를 쓰는 terrain draw 묶음 안에서는 descriptor set을 반복 bind하지 않고, 다른 material/pass는 별도 bind 경로를 유지한다.
- 순간 스파이크를 줄이기 위해 오래된 terrain mesh는 안전 대기 후에도 한 프레임에 몰아서 파괴하지 않고, 설정된 budget 안에서 분산 파괴한다.
- 다음 병목 확인은 전체 UPDATE 시간보다 `requestTerrainLoad()` 내부 단계별 누적 피크를 기준으로 판단한다.
- 순간이동 대응을 유지하기 위해 로딩 범위 전체 선언은 유지하되, 이미 원하는 상태 이상인 청크는 내부에서 재귀 파생 요청을 스킵한다.

## 작업 기록
- 청크 로딩 완료 메시 적용 시 subchunk별 vertex/index 업로드를 반복하지 않고, 한 청크의 subchunk 업로드를 하나의 staging buffer와 하나의 copy submit으로 묶도록 변경했다.
- player mesh와 블럭 편집 리메시는 기존처럼 단일 mesh 업로드 경로를 유지했다.
- terrain vertex shader를 vertex input 방식에서 vertex pulling 방식으로 변경했다.
- terrain GPU vertex buffer는 기존 float 기반 `TerrainVertex` 대신 5개의 `uint32_t`로 구성된 packed vertex 데이터로 업로드하도록 변경했다.
- player mesh는 기존 vertex input 경로를 유지하기 위해 `player.vert` shader를 분리했다.
- terrain GPU 데이터를 vertex 단위에서 quad record 단위로 변경했다.
- terrain index buffer를 제거하고, shader가 quad record 1개에서 6개의 가상 vertex를 생성하도록 변경했다.
- 우상단 terrain 통계의 `VERTICES` 표기를 `QUADS`로 변경했다.

## 결정 사항
- 청크 신규 로딩은 upload submit 수를 줄이는 것이 중요하므로 batch upload를 사용한다.
- 런타임 블럭 편집은 수정 범위가 작으므로 subchunk 단위 리메시/업로드를 유지한다.
- terrain은 GPU 읽기 대역폭을 줄이기 위해 packed SSBO vertex pulling을 사용한다.
- CPU 메싱 결과는 당장은 기존 `TerrainVertex`로 유지하고, 업로드 직전에 packed vertex로 변환한다.
- player는 매 프레임 CPU에서 vertex를 갱신하므로 기존 HOST_VISIBLE vertex input 방식을 유지한다.
- terrain quad record는 기존 CPU 메싱이 만든 4-vertex quad 패턴을 업로드 직전에 압축하는 방식으로 만든다.
- plant/cross처럼 양면 렌더링이 필요한 quad는 reverse winding quad record를 하나 더 만들어 처리한다.
