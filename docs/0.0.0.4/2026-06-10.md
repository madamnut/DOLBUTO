## 작업 기록
- processing recipe 데이터를 단일 `assets/data/recipes/processings.json`에서 process key별 파일 디렉터리 `assets/data/recipes/processings/`로 분리했다.
- 기존 `firing` 레시피는 `firing.json`, 기존 `pyrolysis` 레시피는 `pyrolysis.json`으로 옮겼다.
- `ClientContent`가 processings 디렉터리의 `.json` 파일을 순회하고 파일명 stem을 process key로 사용해 processing recipe를 등록하도록 변경했다.
- 기존 단일 `processings.json`은 processings 디렉터리가 없을 때만 fallback으로 읽도록 유지했다.
- processing recipe 문서와 recipe index 문서를 현재 파일 구조 기준으로 갱신했다.
- `smelt.json`을 추가해 금속 원재료를 도가니 용탕으로 바꾸는 초안 레시피를 등록했다.
- `fluids.json`에 금속 용탕 정의와 텍스처 이름을 추가하고, 유체 텍스처 배열을 콘텐츠의 fluid texture 목록 기준으로 구성하도록 바꿨다.
- 도가니 block entity를 추가해 내부 용탕 종류와 양을 저장하도록 했다.
- 불은 아래 블록의 열원 상태로만 읽고, 도가니가 위 공간의 드랍 아이템을 대상으로 `smelt` processing을 진행하도록 했다.
- 도가니 내부 용탕 수면을 전용 렌더 경로와 `molten.frag`로 그리도록 추가했다.
- 청크 저장 포맷에 도가니 용탕 상태를 저장하되, 기존 fire-only block entity payload도 읽을 수 있도록 legacy 크기 판정을 유지했다.
- fire 구조 판정에서 열린 경계 칸을 leak 방향으로만 기록하고 그 너머 외부 공간은 더 flood fill하지 않도록 변경했다.
- 도가니 용탕 수면과 내부 smelt 감지 AABB를 도가니 메쉬의 블록 좌표 중심 기준으로 맞췄다.
- JSON 파싱 확인을 수행했다.

## 결정 사항
- processing 수가 늘어날 것을 고려해 process key를 레시피 객체 내부의 반복 필드가 아니라 파일명으로 관리한다.
- 도가니 용해는 합금 없이 한 종류의 용탕만 담는 1차 구현으로 제한한다.
- 도가니 용량은 `100`, 광물 원재료 1개가 만드는 용탕량은 `10`, 기본 처리 시간은 `200`틱으로 둔다.
- 금속 용탕 ID는 청크 유체 셀에 패킹되는 흐르는 유체가 아니라 도가니 block entity 내부 상태로만 사용한다.
- 용탕 수면은 렌더링에서 최소 block light 10과 bloom source를 사용해 빛나는 것처럼 보이게 하되, 월드 조명 전파는 아직 추가하지 않는다.
- firing/pyrolysis 구조 판정은 화덕 내부에서 외부로 처음 빠져나가는 1차 leak 방향만 본다. 배기구 밖 외부 공간이 다시 다른 방향으로 열려 있는지는 별도 leak으로 세지 않는다.

## 이슈
- 빌드는 사용자가 직접 수행하는 규칙에 따라 실행하지 않았다.
- 도가니 용탕은 아직 꺼내기, 주형 붓기, 합금, 실제 주변 조명 전파를 구현하지 않았다.
