## 작업 기록 - 플레이어 자세 전환 블렌딩
- 3인칭 플레이어 animation clip 조합이 바뀔 때 직전 렌더 pose snapshot에서 새 pose로 `0.4`초 동안 TRS 블렌딩하도록 했다.
- 전환 도중 다른 자세나 이동 상태로 다시 바뀌면 현재 렌더 pose에서 새 pose로 전환을 다시 시작하도록 했다.
- 1인칭 손은 기존 neutral pose 렌더링을 유지하고, 자세 전환 블렌딩 대상에 포함하지 않았다.

## 작업 기록 - 플레이어 애니메이션 상태 연결
- `run`, `crouchidle`, `crouchwalk`, `proneidle`, `pronewalk` clip을 3인칭 플레이어 상태 선택 규칙에 연결했다.
- `ClientFrame`/`RendererFrame`에 `playerCrouching`, `playerSprinting`을 추가해 렌더러가 자세와 달리기 상태를 기준으로 clip을 선택하도록 했다.
- 정지 상태는 자세별 idle clip, 이동 상태는 자세별 movement clip을 사용하고, 후진 중에는 선택된 movement clip을 역재생하도록 했다.
- `proneidle`/`pronewalk` clip이 있으면 해당 clip의 ModelRoot 회전을 사용하고, fallback 모델에서만 기존 엎드리기 회전을 적용하도록 했다.
- 1인칭 손은 이번 작업에서 animation clip을 적용하지 않고 기존 neutral pose 기반 렌더링을 유지했다.

## 추가 작업 기록
- 플레이어 모델 로딩을 `Characterwithanim.glb` 우선으로 바꾸고, 파일이 없으면 기존 `Character.glb`로 fallback하도록 했다.
- `PlayerModelLoader`가 glTF animation channel을 node index 기준으로 읽고 `translation`/`rotation`/`scale` keyframe을 저장하도록 확장했다.
- `PlayerMeshRenderPath`의 기존 이름 기반 절차 보행을 제거하고, `idle`/`walk` clip 샘플링과 `walkAmount` 블렌딩으로 3인칭 플레이어 보행을 처리하도록 했다.
- 실제 이동 방향이 body yaw 기준 후방이면 `walk` clip을 역방향으로 샘플링하도록 `ClientFrame`/`RendererFrame`에 `playerWalkReverse`를 추가했다.
- 머리 yaw/pitch는 animation pose 적용 뒤 `Head` 제어 node에 추가 적용하며, `Head` mesh node와 group node가 중복되면 group node를 우선 사용하도록 했다.

## 작업 기록
- `torch`, `lit_torch` 아이템 데이터를 추가하고 `wooden_stick + plant_twine + tar -> torch` 제작 레시피를 추가했다.
- fire 블록에 `torch`의 `light` 액션을 적용하면 손에 든 아이템이 `lit_torch`로 교체되도록 `resultTarget: "held"` 상호작용을 추가했다.
- `lit_torch`는 `ignite` 액션으로 기존 점화 규칙을 재사용해 대상 블록 위에 fire를 생성한다.
- `ItemStack`에 `burnTicksRemaining`을 추가하고, 선택 핫바 슬롯 또는 왼손 슬롯에 들린 휴대 조명 아이템만 연소 시간이 감소하도록 구현했다.
- 연소 시간이 끝난 `lit_torch`는 `ash` 1개로 교체된다.
- 플레이어 상태 저장과 드랍 아이템 저장 payload에 `burnTicksRemaining`을 추가하고 기존 저장 크기도 읽을 수 있게 했다.

## 결정 사항
- 횃불은 켜짐/꺼짐 상태를 하나의 아이템 상태로 두지 않고 `torch`와 `lit_torch` 두 아이템으로 분리한다.
- 손에 든 아이템 자체가 변하는 상호작용은 `interactions.json`의 `resultTarget: "held"`로 표현한다.
- `burnableLight`는 아이템 공통 필드는 아니지만 데이터 정의에 optional component처럼 둔다.

## 이슈
- `burnableLight.lightEmission`은 데이터와 UI에는 연결했지만, 실제 주변 지형을 밝히는 휴대 광원 렌더링은 아직 별도 구현이 필요하다.
