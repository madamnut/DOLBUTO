## Decisions
- Water render tuning reuses existing push constant slots instead of increasing the push constant layout.
- Water absorption uses scene depth because the current water pass already samples offscreen scene depth for SSR and occlusion.
- Water alpha now approaches full opacity at grazing angles using `fresnel^4`.
- Water reflection now uses a cubic Fresnel curve with a non-zero base reflection weight.
- Advanced water shader work is postponed until the core game systems are further along.
- `amount` remains `0~100`; only the rendered water surface height is quantized.
- Simple water rendering should remain in the scene pass while it depends on terrain/player depth.
- Climate overlays are generated by the game renderer so previews use the same C++ climate functions as runtime generation.
- Temperature noise uses the same 4D torus tiling approach as precipitation.
- Climate is stored as `uint8_t` per chunk column because biome inputs do not need per-block vertical data.
- Player state is stored outside region files as a fixed 41-byte binary layout with no version field.
- Runtime logging writes both a latest log and a timestamped history log for each run.
- Prop blocks stay in the normal block ID layer; their model and texture slot bindings are defined in block data.
- `dpm` stores quad count and quad vertex data, with no magic or version field.
- Ground prop placement reuses the existing plant/tree placement salt so one random byte decides the ground feature.
- Small prop and plant render offsets reuse deterministic world-coordinate random values and do not change saved block data.
- Block break particles are runtime-only and reuse the existing block texture array instead of adding particle texture assets.
- Prop meshes are emitted double-sided for now because the current terrain pipeline culls backfaces.
- Prop source models now use `.glb`; generated `.dpm` files are runtime cache data.
- Lobby and menu UI will use RmlUi source integration instead of a paid UI middleware.
- RmlUi backend sample code is reference material; runtime integration should live in engine-side UI modules.
- The native menu overlay remains only as a fallback if RmlUi initialization fails.
- Lobby background tiling reuses the existing repeat sampler rather than drawing per-tile sprites.
- FreeType is the font rasterizer for native debug and menu text going forward.
- The renderer stays alive in the lobby; game-scene terrain/save workers and terrain runtime state are active only while the game scene is loaded.
- World time is owned by the application state and passed to the renderer as ticks; sky rendering derives sun and moon directions inside the renderer.
- World creation and last played timestamps are stored as Unix seconds in `world.dat` and formatted only for UI display.
- Lobby rendering skips the game scene and debug text entirely; pause keeps the game scene rendered behind the overlay.
- The sky cycle angle runs in the direction that makes the sun rise after the `06H` start time.
- World selection UI is in place before per-world save path routing; `CREATE` still enters the existing single-world runtime path.
- RmlUi menu documents are now rendered through the engine Vulkan renderer.
- Saved-world list activation uses double-click so single-click selection and scrolling can be separated later.
