## Decisions
- Player-facing HUD and inventory layout files live under `assets/ui`.
- Player UI sprite assets live under `assets/textures/ui/player`.
- Inventory is modeled as its own application screen so existing non-game input routing can handle mouse release and RmlUi input.
- Inventory is not a pause state; it keeps world ticks and player physics simulation running while suppressing movement/camera/block input.
- Item `id` is the runtime primary key, item `key` is the stable authoring/debug key, and item `name` is only a display string.
- Block drops are authored inside `blocks.json` with item keys, then resolved to item ids at load time.
- Blocks with no drops keep an explicit empty `drops` array instead of omitting the field.
- Item data separates dropped-world rendering and held-player rendering with `render.dropped` and `render.held`.
- Dropped items are runtime-only for now; pickup, saving, and held-item rendering remain unimplemented.
- Dropped sprite item side meshes follow the texture alpha silhouette, but adjacent side edges are span-merged for a more stable mesh.
- Dropped sprite side faces sample from opaque pixel centers instead of exact alpha boundaries.
- Dropped-item pickup is visual/runtime-only for now; collected drops are removed but not inserted into inventory yet.

## Issues
- Inventory and hotbar are visual shells only; item slots and item data behavior are not implemented yet.
