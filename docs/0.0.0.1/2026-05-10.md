## Decisions
- Block drop chance and count still use deterministic block/drop-entry rolls, but the visual throw direction is treated as a runtime effect and does not need deterministic replay.
- Dropped items share the player's gravity value and vertical acceleration formula, while keeping item-specific horizontal drag and simple collision.
- Gameplay and save coordinates stay in world space; only scene rendering subtracts the camera position before projection.
- Block hardness belongs to block definitions only; fluid definitions do not define hardness.
- Block breaking crack textures are treated as world block-rendering assets, not UI assets.
- `hardness` is treated as an approximate hand break time in seconds, and `breakPower` scales break speed.
- Inventory belongs to player state and is saved in `player.dat`; the transient cursor stack is not saved.
- Dropped items are the first `WorldEntity` payload type. Entity id, position, velocity, grounded flag, item id, and count are saved; pickup state and render spin are runtime-only.
- Entity changes do not bump terrain revision because that revision is also used for mesh validity; save dirtiness is tracked separately.
- `solidSubchunks` means the fluid-opposite terrain mesh path and includes cube, cross, and prop block render types.
- `fluidSubchunkCounts` is derived runtime data, so it is rebuilt from `fluids` after loading instead of being stored in region files.
- Loaded chunk derived caches now rebuild `emptySubchunks` and `fluidSubchunkCounts` together from `blocks` and `fluids`.
