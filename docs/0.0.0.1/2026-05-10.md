- 최종 블록 파괴 전에 블록 파괴 금 오버레이 단계와 채굴 중 face particle을 추가했다.
- RmlUi 로비 타이틀 이미지 크기를 `520 x 140`에서 `1040 x 280`으로 두 배 늘렸다.
- `player.dat`에 50개 `itemId/count` 슬롯 쌍을 붙이는 방식으로 런타임 인벤토리 저장/로드를 추가했다.
- 전역 드랍 아이템 목록을 청크 소유 `WorldEntity` 엔트리로 교체하고, 드랍 아이템을 청크 payload에 저장했다.
- terrain revision이 바뀌지 않은 entity-only 저장 변경이 건너뛰어지지 않도록 런타임 청크 dirty serial을 추가했다.
- 유체가 아닌 지형 메쉬 저장소 이름을 `rockSubchunks`에서 `solidSubchunks`로 변경했다.
- `fluidSubchunkCounts`를 추가하고 유체 셀이 없는 서브청크는 유체 메쉬 생성을 건너뛰도록 했다.
- 생성된 청크 채우기를 재작업해 `terrainTopY`를 캐시하고, 공통 solid layer를 직접 채우며, 물을 쓰는 동안 fluid subchunk count를 갱신하도록 했다.
- 생성된 청크의 컬럼별 `bedrockHeights`를 캐시하고, 로드된 청크 derived-cache 재빌드를 한 번의 pass로 합쳤다.

## 결정 사항
- 블록 드랍 chance와 count는 여전히 결정적 block/drop-entry roll을 사용하지만, 시각적인 throw direction은 런타임 효과로 보고 결정적 replay가 필요 없다고 본다.
- 드랍 아이템은 아이템 전용 horizontal drag와 간단한 collision은 유지하면서, 플레이어의 gravity 값과 vertical acceleration 공식을 공유한다.
- 게임플레이와 저장 좌표는 월드 공간에 유지한다. 씬 렌더링만 projection 전에 카메라 위치를 뺀다.
- 블록 hardness는 블록 정의에만 속하며, 유체 정의는 hardness를 정의하지 않는다.
- 블록 파괴 금 텍스처는 UI asset이 아니라 월드 블록 렌더링 asset으로 취급한다.
- `hardness`는 초 단위의 대략적인 손 파괴 시간으로 취급하고, `breakPower`가 파괴 속도를 스케일한다.
- 인벤토리는 플레이어 상태에 속하고 `player.dat`에 저장한다. 임시 커서 스택은 저장하지 않는다.
- 드랍 아이템은 첫 `WorldEntity` payload type이다. Entity id, position, velocity, grounded flag, item id, count를 저장하고, pickup state와 render spin은 런타임 전용이다.
- Entity 변경은 terrain revision을 올리지 않는다. 해당 revision은 mesh validity에도 사용되므로 저장 dirty 상태는 별도로 추적한다.
- `solidSubchunks`는 유체 반대편의 지형 메쉬 경로를 의미하며 cube, cross, prop 블록 렌더 타입을 포함한다.
- `fluidSubchunkCounts`는 derived runtime data이므로 region 파일에 저장하지 않고 로드 후 `fluids`에서 재빌드한다.
- 로드된 청크 derived cache는 이제 `blocks`와 `fluids`에서 `emptySubchunks`와 `fluidSubchunkCounts`를 함께 재빌드한다.
