# 2026-05-13

## 작업 기록
- 드랍 아이템 렌더링에 청크 프러스텀 컬링을 추가했다.
- 프러스텀 밖 청크의 드랍 아이템은 렌더 후보 순회에서 건너뛰도록 했다.
- 프러스텀 안 청크에서도 카메라 기준 48블록 밖의 개별 드랍 아이템은 렌더링하지 않도록 했다.
- 드랍 아이템 거리 컬링은 보간된 드랍 아이템 위치와 카메라 위치 사이의 3D 거리 제곱으로 판정한다.
- 드랍 아이템 렌더 컬링 기준을 `docs/design/rendering.md`에 기록했다.
- 드랍 아이템 전체 개수와 드랍 아이템을 가진 청크별 개수를 런타임 캐시로 유지하도록 했다.
- 드랍 아이템 렌더링이 `runtimeChunks` 전체가 아니라 드랍 아이템을 가진 청크만 순회하도록 변경했다.
- 드랍 아이템 생성 직후 주변 같은 아이템 스택으로 병합되도록 했다.
- 드랍 아이템 물리 tick 중 이동한 아이템도 주변 같은 아이템 스택으로 병합되도록 했다.
- 병합 판정은 X/Y/Z 각 축 차이가 모두 0.75블록 이하인 경우로 변경했다.
- 병합을 받은 대상 스택은 위쪽 속도를 최소 `2.0`으로 만들어 살짝 튀어오르게 했다.
- 병합된 드랍 아이템 스택은 count에 따라 1~4개의 겹친 아이템으로 렌더링하도록 했다.
- 시각 복제본 수는 count `1`, `2~16`, `17~48`, `49~99` 구간에 따라 각각 1, 2, 3, 4개로 설정했다.
- 겹친 아이템 복제본은 기존 드랍 아이템 두께 `0.05`블록 단위로 Y 오프셋을 쌓도록 했다.
- 드랍 아이템 렌더링을 CPU 쿼드 재생성 방식에서 정적 item mesh와 instance buffer 방식으로 변경했다.
- 드랍 아이템 instance buffer는 persistent mapping으로 유지해 매 프레임 map/unmap을 하지 않도록 했다.
- 드랍 아이템은 item id 기준으로 instance를 정렬한 뒤 같은 mesh끼리 batch draw하도록 했다.
- 드랍 아이템 전용 vertex shader `item.vert`를 추가했다.

## 결정 사항
- 드랍 아이템 거리 컬링은 청크 단위가 아니라 개별 아이템 단위로 처리한다.
- 프러스텀 컬링은 청크 AABB 단위로 먼저 처리해 화면 밖 청크의 드랍 아이템을 통째로 제외한다.
- 드랍 아이템 렌더 후보 순회는 전체 런타임 청크 순회 대신 드랍 아이템 보유 청크 캐시를 기준으로 한다.
- 드랍 아이템 병합은 엔티티 수를 줄이는 데이터 최적화이며, 렌더링은 count 기반 시각 복제본으로 여러 개가 겹친 것처럼 표현한다.
- 병합 대상은 같은 `itemId`이고 둘 다 획득 중이 아니며 대상 스택에 여유가 있는 경우로 제한한다.
- 병합 범위는 원형 거리보다 축별 박스 판정을 사용해 단순하게 처리한다.
- 렌더 컬링은 렌더 후보만 줄이며, 드랍 아이템 물리, 저장, 획득 판정에는 영향을 주지 않는다.
- 드랍 아이템 정적 mesh는 아이템 텍스처 로드 후 한 번만 생성하고, 프레임별 변화는 instance 데이터로만 전달한다.
- 빌드는 사용자가 직접 수행한다.

## 이슈
- 빌드는 실행하지 않았다.
