# 플레이어 이동·카메라 흔들림 — AI 컨텍스트

## 승인과 범위

공중에서 즉시 방향이 바뀌고 낙하가 느리다는 피드백 후 로컬 Minecraft 소스를 조사했다. 걷기 화면 흔들림도 조사하고 사용자가 `ㅇㅇ 실시`로 구현과 Release 빌드·패키징을 승인했다. 이전 제안 중 임의 중력36/점프9.8/공중15%는 채택하지 않았다. 일반 지상/공중의 원본 수식에 맞추며 현재 게임의 조작과 충돌은 유지한다.

## 물리

Player는 X/Z 속도를 세계축에 저장한다. 카메라를 돌려도 기존 속도는 회전하지 않는다. 20TPS의 매 틱 순서:

1. 수평속도 벡터 길이와 수직속도의 작은 값(<.003블록/틱)을 0으로 정리.
2. 실제 고체 발판 확인. 점프시 수직속도 최소 .42블록/틱, Shift이면 수평 시선방향으로 .2블록/틱 추가.
3. 지상 .1 / 공중 .02블록/틱² 입력 가속(Shift ×1.3), 정규화한 WASD에 .98 입력감쇠.
4. 속도만큼 기존 복셀 충돌 스윕으로 이동. 벽/천장/바닥 충돌 축 속도는 0.
5. 수평속도에 틱 시작 지상 여부로 .6×.91 또는 .91을 곱한다. 수직속도는 (속도-.08)×.98.
6. 최종 발판 여부 갱신. 위치는 매 렌더 프레임 이전/현재 틱 사이 보간, 순환경계 최단거리와 충돌 클립 유지.

C++ 저장 단위는 블록/초이므로 위 틱 속도 상수는 ×20으로 변환한다. 기존 플라이 24/100블록/초, Space 유지 연속점프/두번 모드변경, 플레이어 .7×.7×1.75, 눈높이1.6, 부분눈 충돌/미로딩 차단 유지. 모드변경·텔레포트·재생성은 속도와 보행위상을 초기화한다. 메뉴 일시정지는 입력과 물리를 멈추며 속도를 매 프레임 초기화하지 않는다.

평지 정상속도 .1×.98/(1-.546)×20 ≈4.317블록/초, 달리기≈5.612. 점프 원식의 이산 궤적 꼭대기≈1.2522블록, 평지 복귀12틱≈.6초. 낙하속도는 장시간 낙하하면78.4블록/초에 접근한다. 바닥에 서 있을 때 저장 수직속도는 중력적용후 -1.568블록/초지만 다음 충돌에서 실제 이동이 막히므로 추락하지 않는다.

Minecraft 전체 이동 복제가 아니다. Shift는 기존 모든 수평 방향의 달리기 입력이며 원본 달리기 자격/배고픔/포션/물수영/자동계단/얼음마찰은 추가하지 않는다. 모든 고체는 일반마찰이며 기존 몸체 크기/축순서 충돌을 유지한다. 반복 점프는 기존 즉시착지 재점프 규칙으로 원본 점프쿨다운을 추가하지 않는다.

## 보행 화면

틱 직전 지상 수평속도/20에서 목표 진폭 min(.1,speed)를 구하고 진폭 += (목표-진폭)×.4. 공중 목표0. 실제 충돌 후 수평 이동거리×.6을 위상에 더한다. 프레임 보간한 위상에 -π를 곱한다. sin위상×진폭×.5의 가로이동, -abs(cos위상×진폭)의 세로이동, Z회전 sin위상×진폭×3도, X회전 abs(cos(위상-.2)×진폭)×5도. 위상은 2주기 단위로 이전·현재를 함께 줄여 장시간 오차를 제한한다.

원본의 뷰공간 이동 T를 실제 렌더 카메라 위치로 환산한다. 회전 Q, 원래뷰회전 R에 대해 offset=-(QR)^-1 T, 최종 P Q R과 옮긴 카메라 원점을 함께 사용하므로 역투영/물반사/TAA/구름의 좌표가 일치한다. 기존 카메라 충돌 스윕으로 작은 offset도 제한하고 벽 근처에서는 회전도 같은 비율로 축소한다. 논리 player_eye/forward와 yaw/pitch는 바꾸지 않아 조작·블록판정·플레이어 충돌은 흔들리지 않는다. 월드 로딩 중심도 플레이어 위치 그대로다. 걷기 1/3인칭 적용, 플라이 비활성. 원본과 다른 근평면충돌 보완이며 벽 근처 동작이 픽셀동일하지는 않다.

옵션 > 화면 > 걷기 화면 흔들림. GameSettings.view_bobbing 기본true; schema10에서 boolean 필수, schema1..9는 메모리에서true 기본값. 원본 설정 파일은 자동 이행 저장하지 않으며 사용자가 옵션 변경할 때 저장한다. 비활성화는 물리나 내부 위상누적을 바꾸지 않으며 전환시 TAA 이력을 무효화한다.

## 검증

검증 결과는 docs/verification.md의 동일 날짜 항목을 따른다. 자동 테스트·합성 입력·컴퓨터 유즈는 추가하지 않는다. 실제 걷기/점프 조작감과 보행 중 화면은 사용자 플레이 확인이 필요하며 정지화면 런타임 점검을 동작 검증으로 대체하지 않는다.
